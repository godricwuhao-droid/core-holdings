# ADR-017: Token 类产品的数量/单价口径与普通产品统一（数量=份数，单价=元/份）

## Status
Accepted（2026-10-20，业务已拍板：与软件等普通产品一致）

## Context
BUG-20261020-#4：同一 Token 产品上并存三套量纲——产品登记按"原始 Token 个数"（quantity=3 亿、页面展示"¥33333.33/万Token"）、订单按"1 份"成交（qty=1, amount=582000）、前端派生价 `amount/qty/1e4`（元/万Token）与后端 `_derived_price = amount/qty` 差 1e4 倍。审核改价会把 `amount/qty`（元/份）写回 `salePrice`，页面却按"元/万Token"展示，金额跳变 1e4 倍；viewer 免填金额兜底 `salePrice × qty` 因量纲混乱可能错 1e4 倍。

## Decision
1. **统一口径**：Token 产品与普通产品完全一致——`quantity` = 可售份数，`salePrice` = 元/份，订单/明细 `qty` = 份数，金额 = 元。"每份内含多少 Token"只写进 `spec`/`saleDetail` 描述，不参与任何计算。
2. 派生价统一为 `amount / qty`（元/份）：
   - 前端 `derivedUnitPrice` 去掉 `/1e4`，文案改"元/份"（或按产品 `unit` 展示）；
   - 后端 `_derived_price` 维持 `amount/qty` 不变；审核回写 `salePrice` 逻辑不变（口径统一后自然正确）。
3. 产品列表/详情/登记表单中"元/万Token"的特殊文案（`list.vue` 等）改为与普通产品一致的"元/{unit}"展示。
4. 免填金额兜底 `salePrice × qty` 维持不变（量纲统一后正确）。
5. **存量数据**：本次不自动迁移。现有 `CH-SAT-001`（quantity=3 亿、salePrice=33333.33）按新口径语义已失真，由业务在页面上手工改为真实可售份数与元/份单价；后端在资产编辑时不做强校验拦截。存量 `qty=1` 订单数据与新口径天然兼容，不动。

## Consequences
- 变容易：全系统只有一套计价公式（金额 = 单价 × 份数，元），前后端派生价/回写/兜底自然一致；Token 产品不再有特殊分支的展示逻辑。
- 变难：产品登记表单的"数量"对 Token 产品从"Token 总个数"变为"份数"，需要业务重新登记现有 Token 产品（一次性人工操作）；已按"元/万Token"对外报价的场景需业务自行换算。
- 可逆性：中高。代码改动回滚容易；但产品 quantity/salePrice 若已被按新口径修改，回滚代码不会自动恢复旧值（建议修改前记录原值）。
