# ADR-058: 流转日志与分配下拉显示「姓名」而非「账号」

## Status
Accepted（2026-11-10，已实现 + 自测/Architect 代码核对通过：新增共享 `utils/userName.ts`（`nameOf`/`resolveUserNames`：全量启用账号建表、**最长优先**排序、**词边界** lookbehind/lookahead、空 name/未知回退、幂等）+ `composables/useUserNameOptions`（`/users/options/all` 缓存，多页复用不重复请求）；① 抽屉流转日志 detail 展示处 `resolveUserNames`（存量+新日志同时生效，detail.vue 经自查无该区块无需改）；② `TransferDialog` 选项 label 改只显示姓名（`:value` 仍 username、`claimProject` 提交不变）+ 当前负责人/接手给我走 `nameOf`；自测覆盖 biz01/biz011 子串互不误伤、空 name 回退、分配/改派提交值仍 username、vue-tsc 0）

## Context
`/sales/projects` 抽屉「流转过程」里，claim/分配/改派/撤销/重新提交 的日志 `detail` 文本把**商务负责人的账号（username）** 写进了自由文本（如「商务负责人绑定为 editor」），前端**原样渲染** → 用户看到账号而非姓名；而同页操作人列已显示姓名（经 `ownerLabel` 映射），观感不一致。另外「分配」下拉选人显示「姓名（账号）」，用户希望**只显示姓名**。
需求：① 抽屉流转过程显示姓名、不显示账号；② 分配下拉只显示姓名。

## Decision
- **username 作稳定存储标识、name 作展示标签**：日志 `detail` 与 `Contract/Project.businessOwner` 继续存 **username**（稳定、可解析、用户改名后旧日志仍解析到当前姓名）；**展示层做 username→name 解析**（不耦合日志文本格式）。
- **① 流转日志**：在展示 project 流转日志 `detail` 的**所有**位置（列表抽屉 + 详情页等），用 username→name 映射（`GET /users/options/all` 的全量启用账号）把 `detail` 中出现的 username 替换为对应 name——**最长优先 + 词边界**，未知 username / 空 name 回退原样。**前端解析 → 存量 + 新日志同时生效**，不动后端、不迁移数据。
- **② 分配下拉**：`TransferDialog` 选项 label 由「姓名（账号）」改为「**姓名**」（`o.name || o.username` 兜底）；`value` 仍提交 username（后端 `businessOwner` 不变）。同对话框「当前负责人」「接手给我」的裸 username 一并按姓名显示。
- **共享 helper**：抽一个 username→name 解析工具（供多展示点复用），替代各页私有的 `ownerLabel`。

## Consequences
- 易：单一展示层改动，存量/新日志一致显示姓名、与操作人列口径统一；分配下拉更简洁。
- 难/代价：展示时解析依赖「username 在文本中可定位」——已用最长优先 + 词边界降低误替换；若某 username 恰为另一 username/name 的子串仍有极窄风险（用户名为拉丁、姓名为中文，实际碰撞极低）。
- **未选方案**：改后端 4 处写入存 name（`services.py` claim L2462/L2465、撤销 L1611、重新提交 L1716）——语义更"正"，但**存量日志仍是账号**（需额外 backfill 解析）、用户改名后旧日志显示旧名；综合取展示层解析。
- 可逆性：**高**（纯展示层 + 一处 label，无 schema/数据迁移）。
