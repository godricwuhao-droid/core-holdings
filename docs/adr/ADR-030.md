# ADR-030: 可见性判定收口（文件 ACL + 日志/流水过滤）

## Status
Accepted（2026-10-22，来源：`business-logic-bugs-20261022.md` BUG-02 / BUG-13 / BUG-30 / BUG-32）

## Context
viewer（生态人员）只能看自己下单的项目（ADR-016 之后的可见性口径）。当前"过滤"分散在 3 个地方，且判定方式各不相同：

| 读路径 | 现状 | 问题 |
|---|---|---|
| `bootstrap.outbounds/flows` | 按 `projectId`/`contractId`/`ref` 前缀结构化过滤 | 正确 |
| `bootstrap.logs` | `target == "project"` 用 **detail 文本里的 `SP-` 正则**、`target == "outbound"` 用 `CK-` 正则；`target == "contract"` **直接放行** | 文案一改即误判；合同日志（客户名/金额/签订时间）对 viewer 泄露 |
| `bootstrap.files` | 全量返回（49 条 vs 产品实际引用 24 个） | 孤儿文件可被枚举下载（`GET /files/{name}` 仅校验登录） |
| `GET /assets/{id}/flows`（分页端点） | 完全不过滤 | 与 bootstrap 口径不一致，绕过分页端点即可拿到他人合同号/数量/金额 |
| `GET /users/options` | viewer 可拿全部商务/管理员名单 | 内部人员信息暴露（`/users/options/all` 已收敛，此处漏改） |

## Decision
1. **单一判定函数**：新增 `services/user_visible_*()` 系列（`visible_project_ids(user)` / `visible_contract_ids(user)` / `visible_flow(f, ctx)` / `visible_log(l, ctx)` / `visible_file(name, ctx)`），bootstrap 与全部分页端点**共用**。
2. **判定依据只用结构化外键**（`projectId` / `contractId` / `assetId` / `uploadedBy`），**禁止**再用 detail 文本正则或项目名匹配。
3. **文件可见性**：
   - 被任一产品引用（`assets.contractFile` / `assets.featureDoc` / `asset_deliverables.file`）→ 所有登录用户可见（产品目录本身公开）；
   - 未被任何产品引用（孤儿）→ 仅 `uploadedBy == 当前用户` 或 admin 可见；
   - `bootstrap.files` 与 `GET /files/{name}` 使用同一规则（下载时 404，不返回 403，避免探测文件名存在性）。
4. **日志/流水**：`target == "contract"` 按 `contractId ∈ visible_contract_ids`；无法归属的日志（无 targetId 且非 asset/setting）→ 对 viewer 一律过滤。
5. **`GET /users/options` 提为 `require_editor`**；前端商务负责人筛选对 viewer 不渲染。

## Consequences
- **变容易**：新增资源只要有外键就能接入可见性；安全边界可单测（给定用户断言可见集合）。
- **变难**：viewer 侧"能看到的文件/日志"会变少（属预期）；孤儿文件需要 admin 定期清理（本次不做自动回收）。
- **可逆性**：**中**。判定函数集中后回退成本低，但"卡片上少了某条日志"这类体验回退不易被立即发现，需要 QA 用例覆盖。
