# ADR-050：审核阶段可编辑性增强（合同总价 / 客户名称 / 数量）

- 状态：Accepted
- 日期：2026-11-03
- 相关：ADR-012（review 唯一 pending→active 出口）、ADR-018（审核改价不回写挂牌价）、ADR-029（`contractAmount` = Σ 明细）、ADR-032/033（数量条件更新、不变量破坏显式 500）、ADR-047（服务期限审核可改）、ADR-048（金额精度 ≤6 位小数）、ADR-049（审核链路不受参考区间限制）

## 背景

商务在 `POST /projects/{id}/review`（`action=confirm`）环节目前只能改**行级单价 / 行金额 / 服务期限**。实际审核需要三处额外修正，现状都不支持：

1. **总价**：合同/项目总额是 `Σ 明细` 派生、只读；商务拿到的是客户谈定的「合同总额」，希望直接填一个总额，而不必逐行改单价。
2. **客户公司名称**：`Contract.customer` 是权威存储，但审核接口不接收该字段，下单时填错只能在「撤销重下」里改。
3. **数量**：审核接口无 `qty`，`services.review_project` docstring 明令「数量审核时不可改（需改数量→驳回重下）」。

本次把这三项纳入审核可编辑范围。经确认口径：**总价 = 合同级**（每客户一个总额，按比例分摊到明细，严格保持 `合同总额 = Σ 明细`）；**数量 = 普通 + repeatSale 可改、遥感行恒 1 不可改**，改大时校验可用库存、不足则本次确认不能通过。

## 决策

### 1. 请求契约（新增字段全部可选，向后兼容）

`ReviewItemInput`（schemas.py）新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `qty` | `int \| None` | 行数量。**仅非遥感行**生效（遥感行 `qty ≡ 1`，传入忽略）；≥ 1 |

新增 `ReviewContractInput`，`ReviewInput` 新增 `contracts: list[ReviewContractInput] = []`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `contractId` | `int` | 销售记录（合同）主键 |
| `customer` | `str \| None` | 客户公司名称，改写 `Contract.customer`；非空、trim 后 ≤ 128 字 |
| `amount` | `float \| None` | **合同总价**（元，> 0 且 ≤ 6 位小数），按该合同内各明细行金额**比例分摊**回写 |

`ReviewInput = { action, reason, items[], contracts[] }`。`action=reject` 时忽略 `contracts` 与 `items[].qty`（驳回仅关闭并释放锁定，行为不变）。响应保持 `{"ok": true}`，前端 `refresh()`（不新增返回结构）。权限保持 `require_editor`。

### 2. 行级解析（confirm，非遥感行；遥感行沿用现有「只改 amount」）

按行 `pricingMode` 决定权威输入：

- **unit 模式**（`amount = price × qty`）：`price` 权威。`finalQty = qty ?? 原值`，`finalPrice = price ?? 原值`，`finalAmount = quantize(finalPrice × finalQty, 1e-6)`。（UI 只改单价，`amount` 派生；即使传入 `amount` 也以 `price × qty` 为准。）
- **amount 模式**（包量/卫星 Token，合同金额权威）：
  - 传了 `amount` → `finalAmount = amount`，`finalPrice = quantize(amount / finalQty, 1e-6)`（单价派生）；
  - 只传 `qty`（未传 `amount`）→ **金额按数量比例缩放**：`finalAmount = quantize(原amount × finalQty / 原qty, 1e-6)`，`finalPrice` 随之派生；
  - 都未传 → 保持原值。
- **遥感行**：`qty ≡ 1` 不可改，仅可改 `amount`（现有行为不变）。

金额一律「元」，`> 0` 且 ≤ 6 位小数（ADR-048），`Decimal` 量化 1e-6。**审核链路不走参考区间**（ADR-049，改数量导致的折算单价变化同样豁免）。

### 3. 合同总价分摊（在第 2 步行级解析之后，逐合同）

若 `contracts[].amount` 传入：
- 校验 `> 0` 且 ≤ 6 位小数。
- 令 `target = amount`，`sum = Σ 该行 finalAmount`（sum 必 > 0，因各行 `amount > 0` 已有守卫）。
- 每行 `finalAmount = quantize(finalAmount / sum × target, 1e-6)`；**四舍五入残差落到金额最大行**，使 `Σ finalAmount == target` 精确成立。
- 每行 `finalPrice = quantize(finalAmount / finalQty, 1e-6)` 重新派生。
- `Contract.contractAmount = Σ 行 = target`（保持 ADR-029 不变式）。

> 优先级：**合同总价最后生效**——若同时改了行与总价，行先按第 2 步解析，再由总价按比例覆盖到精确合计。

### 4. 客户名称

- `contracts[].customer` → 写 `Contract.customer`（权威）。校验：trim 后非空、≤ 128 字，否则 400。
- 冲突守卫：若同项目内另一合同改后 `customer` 相同且**明细产品集完全相同**（对齐建单期 `seen_contracts` 判定口径，非「任意重叠」）→ 400。
- `Project.customer` 由 `_recompute_project` 重新派生（单客户=该值，多客户=空串，前端显「N 位客户」）。

### 5. 数量与库存锁定（非 repeatSale、非遥感行）

订单在**建单（pending）时已锁定** `lockedQty`。审核改数量 = 调整既有锁定：
- `delta = finalQty − 原qty`。
- **非 repeatSale**：走既有原子条件更新（ADR-033），净效果 = 该订单持有 `finalQty` 锁定。`delta > 0` 时校验可用库存 `= asset.quantity − lockedQty − shippedQty ≥ delta`（`lockedQty` 已含本订单原锁定，**勿再减 `原qty`**——减了会宽松原qty 个单位导致超卖），不足 → **400「第 X 行可用库存不足（需 N，当前可售 M）」**，整个 confirm 事务回滚（不半提交）。释放不足等不变量破坏 → 显式 500 + 审计（不静默）。
- **repeatSale**：不锁数量、只计次，改数量无库存约束。
- 全部在 confirm 单事务内完成。

### 6. 影响

| 层 | 变更 |
|---|---|
| 后端 `schemas.py` | `ReviewItemInput` + `qty`；新增 `ReviewContractInput`；`ReviewInput.contracts` |
| 后端 `services.py` `review_project` | confirm 分支：行级 qty 解析 + 库存锁定调整；合同总价比例分摊 + 残差归最大行；`customer` 改写 + 冲突守卫 + `Project.customer` 重派生；保留现有守卫（空明细/pending_asset/amount≤0）与 ADR-049/018/048 口径 |
| 前端 `review.vue` | 每合同卡加「合同总价」输入（`el-input-number :controls="false"`）+「客户公司名称」输入；行数量由只读文本改为可编辑（非遥感，`el-input-number`），去掉「数量不可修改」文案；变更检测 + 提交 payload 增 `contracts[]` 与 `items[].qty` |
| 前端 `api/index.ts` / `types.ts` | `reviewProject` payload 与 `ReviewInput`/`ReviewContractInput` 类型对齐 camelCase |
| 数据结构 | **无 schema 变更、无迁移**（customer/qty/amount 均为既有列） |
| 行为变化 | 审核由「只改行级单价/金额/期限」扩展为「+ 合同总价 + 客户名 + 非遥感数量」；驳回路径行为不变 |

## 风险与回滚

- 风险 1：改数量放大可能超卖 → 原子条件更新 + 可用库存 400 拦截，回滚不留半态。
- 风险 2：合同总价分摊会改写商务未逐行设置的行金额 → 前端以「总价权威」提示「确认后按明细比例分摊」；总额精确命中、不变式不破，符合「填总额」的业务预期。
- 风险 3：分摊四舍五入 → 残差归最大行，保证 `Σ 行 == 总额` 精确。
- 回滚：移除 `contracts`/`qty` 字段与对应解析即可，无数据修复成本。

## 验证（实现后由 backend-dev 自测 + qa 回归）

副本库实测，覆盖：
1. 改合同总价 → `contract.contractAmount` == 输入值、Σ 行 == 总额、各行单价重派生、`project.contractAmount` 级联；
2. 改客户名 → `contract.customer` 更新、`project.customer` 重派生（多客户→空）、冲突名 400；
3. 非遥感 unit 行改数量（放大/缩小）→ 金额按 `price×qty` 重算、`lockedQty` 净调整正确、放大超可售 400 且事务回滚；
4. repeatSale 行改数量 → 不锁库存、仅计次；
5. 遥感行 `qty` 传入 → 忽略、恒 1，仅 amount 可改；
6. 审核链路不触发参考区间 400（ADR-049 保持）；不改挂牌价（ADR-018）；
7. `action=reject` → 新字段被忽略、行为与现状一致；
8. 多合同项目：各合同总价独立分摊、项目总额 = Σ 合同。
