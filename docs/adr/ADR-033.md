# ADR-033: 关键写路径的并发与幂等（checkout / 状态变更）

## Status
Accepted（2026-10-22，来源：`business-logic-bugs-20261022.md` BUG-10）

## Context
- `POST /cart/checkout`：读购物车 → 校验 → 建项目 + 锁量 → 清空购物车，单事务但**无幂等键**。
- `_change_contract_status_core`：`if status == from_status: return` 基于会话内存状态，非条件更新。
- `apply_item_lock`：`a.lockedQty = max(0, a.lockedQty ± qty)` 是读-改-写。
- 数量校验与加锁分离（`1093-1130`），期间无锁/版本号；FastAPI 同步端点跑线程池，SQLite 只保证写串行，不防"读-判断-写"跨事务。

结果：并发双击「结算」/「确认交付」可重复锁量、重复生成交付单、`soldAmount` 多计；`max/min` 夹断把错误钉在边界上，事后无告警。

## Decision
1. **checkout 幂等**：请求体新增可选 `requestId`（前端 `crypto.randomUUID()`，同一次提交复用）。后端以 `(userId, requestId)` 唯一键记录，重复请求直接返回**首次生成的同一 project**（HTTP 200，`idempotent: true`）。
   - 保留期 24h，过期清理由启动迁移（结构）+ 运维脚本（数据）负责。
2. **状态变更条件更新**：`UPDATE contracts SET status=:new WHERE id=:id AND status=:old`，`rowcount == 0` → 400「状态已变更，请刷新后重试」。
3. **数量原子扣减**：`UPDATE assets SET lockedQty=lockedQty+:q WHERE id=:id AND quantity-lockedQty-shippedQty >= :q`，`rowcount == 0` → 400（沿用现有文案），**取消 `max(0, ...)` 静默夹断**，改为显式不变量校验并写审计告警。
4. **前端**：checkout / 交付 / 终止按钮在请求期间 `loading` + 禁用；`requestId` 在用户点击开始时生成，重试沿用、成功后清空。

## Consequences
- **变容易**：重复提交变成幂等返回；错误不再被夹断掩盖，可观测。
- **变难**：SQLite 上条件更新仍需写锁串行（性能足够，当前数据量小）；`idempotency` 表需要清理策略。
- **可逆性**：**高**。`requestId` 为可选字段（前端不传即退化为旧行为）；条件更新只改变"并发时的结果"，单线程顺序调用行为不变。
