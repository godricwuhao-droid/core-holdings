# ADR-038: 遥感可售明细级「可重复售卖」开关（默认关闭 + 逐条可控）

## Status
Accepted（2026-10-22，业务需求：明细默认单次售卖，需要能逐条控制）

## Context
现状三个问题：
1. **默认值反了**：`rs_items.repeatSale` 默认 `true`（ADR-011 时期的口径"只计次不扣量"），而遥感数据实际按"省×精度×月份"逐期售卖，同一期通常只卖一次；默认开启导致售出后到期仍可重复下单。
2. **无法逐条控制**：`RsItemInput` **没有** `repeatSale` 字段（`schemas.py:156-168`），新增/编辑明细时前端根本没有该入参；列表里「可重复售卖」只是只读标签（`assets/detail.vue:842`）。
3. **可售口径与新语义冲突**：`availableCount`（UI-OPT-20261022）把"被非终止销售记录占用的明细"一律扣减；若某明细开启了重复售卖，售出后仍应可售，却会被扣掉。

## Decision
1. **默认关闭**：`models.RsItem.repeatSale` 默认 `False`；`schemas.RsItemInput.repeatSale: bool = False`（入参与模型一致）。
2. **逐条可控**：
   - 明细新增/编辑弹窗增加「可重复售卖」开关（默认关）；
   - 列表「可重复售卖」列由只读标签改为 **`el-switch` 直接切换**（切换即 `PUT /rs-items/{id}` 提交整行，失败回滚开关并提示）。
3. **可售口径对齐语义（修订 2，2026-10-22，业务方方案）**：明细引入**状态标识**，与外层产品逻辑完全同构——
   - `rs_items.status ∈ {in_stock(可售), all_sold(已售罄)}`，默认 `in_stock`；
   - 容器 `availableCount` = **`status = in_stock` 的明细条数**（不再做 join 推导）；
   - 状态流转：下单锁定（非 repeatSale 明细）→ `all_sold`；释放（终止/撤销/驳回/删项目/撤销交付回 locked）→ `in_stock`；交付 → 保持 `all_sold`；`repeatSale = true` 的明细**永不置** `all_sold`（只计次）；
   - 下单护栏：`repeatSale = false` 且 `status = all_sold` → 400「该可售明细已售罄」。
   - 外层呼应：容器 `assets.quantity` = 明细条数（已由 `_sync_container_quantity` 维护），故 `quantity − lockedQty − shippedQty` 与 `count(status=in_stock)` 恒等，两套口径不会打架。
4. **存量归一**：现有 `rs_items`（60 条，均属 `#29`）一次性置为 `repeatSale = 0`；按 ADR-031 走 `backend/scripts/` 显式脚本（dry-run + 备份 + OpLog），**不放启动迁移**。

## Consequences
- **变容易**：默认行为符合业务直觉（一期卖一次）；少数需要重复售卖的月份可单独打开，无需整体改口径。
- **变难**：可售数计算多一个条件（`repeatSale` 参与占用判定），需与前端 `availableQty` 的展示口径保持一致；列表内联开关引入"行级写操作"，需要请求期间禁用同行开关避免连点（与 BUG-25 同思路）。
- **可逆性**：高。回退 = 默认值改回 true + 脚本反向置位；无表结构变更。
