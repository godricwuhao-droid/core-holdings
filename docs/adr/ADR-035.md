# ADR-035: 资产主体可维护（entities 表 + 设置页维护 + 前端清单动态化）

## Status
Accepted（2026-10-22，业务要求：平台增加"添加资产主体"的入口）

## Context
「资产主体」（我司签约主体，`assets.subject` 存**公司全称**）目前在 `frontend/src/types.ts` **硬编码** 4 家：

```ts
export const ENTITIES: Entity[] = [
  { name: '蜂云时代科技有限公司', short: '蜂云时代' },
  ...
]
```

消费点：建产品页「所在主体」下拉（`assets/create.vue:307`）、产品列表主体筛选（`assets/list.vue:436`）、各页 `entityShort()` 简称展示。新增主体必须改代码发版，且简称映射与存储值耦合在前端常量里。

库内现状（2026-10-22 只读核对）：`assets.subject` 实际取值恰好是这 4 家，无游离值。

## Decision
1. **新增 `entities` 表**：`id / name（公司全称，UNIQUE）/ short（展示简称）/ createdAt / updatedAt`。
   - **不**复用 `base_records`（其字段语义是 name/contact/phone/remark 的"联系人"型，主体只需 全称+简称，硬塞 contact/phone 会留两个无意义空列）。
   - 启动迁移：建表 + **存量回填**（`INSERT ... SELECT DISTINCT subject FROM assets WHERE subject<>''`，幂等，标记入 `schema_migrations`，ADR-031 口径）；`short` 默认取 `name`，由管理员在设置页修正。
2. **API**（契约见 `api-contracts.md` ENTITIES-20261022 批次）：
   - `GET /entities`：登录即可（viewer 建产品页下拉也需读取）；
   - `POST /entities`、`PUT /entities/{id}`：`require_editor`；
   - `DELETE /entities/{id}`：`require_editor`；**被任一产品引用（`assets.subject == name`）→ 400「该主体下存在 N 个产品，不可删除」**（H7 服务层校验口径，SQLite 无外键）。
3. **设置入口**：`/settings/entities`（菜单挂「基础设置」组，与「账号与审计」同组；viewer 不显示，路由守卫 `canWrite` 拦截）。UI 走既有 `settings/users.vue` 表格先例（`.form-card` / `el-table` / 弹窗 `.dlg-form`，§6 硬约束）。
4. **前端清单动态化**：`bootstrap` 下发 `entities[]`（全量，无可见性问题——主体非敏感商业数据）；`types.ts::ENTITIES` 常量**删除**，改由 `db.entities` 提供；`entityShort()` 改读 `db.entities`（查不到回退原值，兼容未刷新快照）。
5. **校验联动**：建产品时 `subject` 仍必填（下拉即 entities 清单，天然闭集）；`PUT /assets` 改主体时后端**不**校验"是否在 entities 表"（存量宽松 + 避免迁移期 400），但前端下拉保证新值必在表内。

## Consequences
- **变容易**：新主体业务自助增删（秒级），无需发版；简称展示与存储值解耦（改简称不再动代码）；主体清单有了单一事实来源（表），前后端一致。
- **变难**：多一张表 + 3 个端点 + 1 个页面；`entityShort()` 从纯常量查询变为镜像查询（首次 bootstrap 前为回退展示，无功能影响）；主体改名（PUT）只改 `name` 会**失联存量产品**（`assets.subject` 仍存旧全称）——设置页改名需二次确认提示，属接受的行为（公司更名是低频运营动作）。
- **可逆性**：**高**。回退 = 删表 + 前端恢复常量；数据迁移是纯增量（回填只加行不改行）。
