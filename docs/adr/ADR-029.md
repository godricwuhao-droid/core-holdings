# ADR-029: 下单校验单一出口 + deprecated 下单端点下线

## Status
Accepted（2026-10-22，来源：`docs/business-logic-bugs-20261022.md` BUG-07 / BUG-08 / BUG-18）

## Context
系统存在 4 个可创建销售项目的入口：

| 入口 | 权限 | 参考区间校验 | 服务期限必填 |
|---|---|---|---|
| `POST /cart/checkout` | require_order（含 viewer） | ✅ | ✅（ADR-022） |
| `POST /projects` | require_editor | ❌ | ❌ |
| `POST /sales/order` | require_order（含 viewer） | 部分 | ❌ |
| `POST /projects/{id}/resubmit` | require_order（含 viewer） | ❌ | ❌ |

造成三个已确证缺陷：
1. 非购物车入口可绕过 ADR-018/021 参考区间与 ADR-022 必填，且 `POST /sales/order`、`/resubmit` 对 **viewer 开放**；
2. `contractAmount` 若客户端传入则直接覆盖，不与 Σ 明细校验（`services.py:1001`），pending 期报表与审批依据失真；
3. 前端 unit 行提交的 `price` 被 `_item_pricing` 原样采信（`services.py:313`），配合"切换产品不重置单价"直接产生错误金额。

根因不是某一条校验写错，而是**同一业务不变量被复制到 4 处、且没有任何一处是权威的**。

## Decision
1. **建立唯一权威校验链**：`_create_project_core` 内按顺序执行「明细存在性 → 明细归属/qty → 折扣率 → 服务期限 → 参考区间/金额 → 按 assetId 聚合数量」；`_item_pricing` 对 unit 行同时做区间校验（不再只信 `price`）。
2. **金额不变量**：`contractAmount` 一律重算 = Σ 明细 amount；客户端显式传入且与 Σ 不一致 → **400**「合同金额与明细合计不一致」。前端建单页保持只读。
3. **`POST /sales/order`、`POST /projects/{id}/resubmit` 返回 `410 Gone`**（detail：该接口已下线，请使用购物车结算）。
   - 已核实前端不再调用（`api/index.ts:927,540` 已删封装），无前端联动。
4. **`POST /outbounds`（手动补录交付）**：`qty <= 0` 400；`asset.type == '遥感数据'` 容器 400；项目状态 pending/terminated 400（补齐 ADR-015 缺口）。

## Consequences
- **变容易**：新增下单入口自动继承全部校验；审计/对账可用一条规则解释所有单据；viewer 无法再从旁路建单。
- **变难**：`_create_project_core` 变重，需要按错误优先级排序（一次报全 vs 首错即断需明确）；外部若仍有直调 `/sales/order` 的脚本会立刻 410（可接受：本平台为内网本地部署，已确认无前端入口）。
- **可逆性**：**高**。410 是两行路由改动，恢复旧行为只需接回 `_order_core`，但**不建议回退**（回退即重新打开旁路）。
