# ADR-022: 购物车结算必填口径（客户 + 销售金额 + 服务期限）

## Status
Accepted（2026-10-24，业务拍板：购物车所有都是必填项）

## Context
ADR-018 §3 曾设计"生态下单金额选填、留空按挂牌价成交"，ADR-020 服务期限选填。业务反馈：留空兜底导致下单信息不完整（金额随意填 10 元、不填服务期限），结算前必须把每行关键信息补齐。

## Decision
1. **结算必填（前后端同口径）**，逐行校验，缺项 400 / 前端拦截：
   - 客户（已有）；
   - 销售金额 > 0（整数元，**所有行类型**：unit/amount/遥感明细行）——**取代 ADR-018 §3"留空=原价成交"兜底**，"留空按挂牌价"提示与兜底逻辑下线；
   - 服务期限起止（普通产品行：serviceStart 与 serviceEnd 均必填，start ≤ end）；
   - **例外：遥感明细行服务期限仍不填**（ADR-020 口径：期数即服务时间），其余必填项相同。
2. **校验时点**：行更新（PUT/PATCH cart）仍允许暂存缺项（加购后可分批补）；**checkout 结算时强制齐全**（后端 400 逐行报缺项，前端结算前置校验同口径拦截并标红缺项）。
3. 区间校验（ADR-018/021）不变：必填金额仍须落在参考区间内（未设区间不限制）。

## Consequences
- 变容易：结算单信息完整，商务审核不再遇到 10 元占位金额和空期限；前端"必填"视觉口径统一（红色必填标记）。
- 变难：viewer 下单步骤变多（每行要填金额+两个日期）——业务已接受；"留空兜底"相关前后端逻辑成为死路径需清理（购物车金额兜底提示、后端 amount 为空回退 salePrice×qty 分支）。
- 可逆性：高。校验分支 + 文案，revert 即恢复选填。
