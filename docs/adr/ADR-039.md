# ADR-039: 购物车折扣功能下线（Deprecates ADR-023）

## Status
Accepted（2026-10-22，业务要求：折扣功能直接删除，不需要了）

## Context
ADR-023 曾引入「购物车折扣率选填快捷入口」：填折扣 → 前端按 `salePrice × 折扣` 回填「销售金额」。实际运行后的问题：
1. **双入口冗余**：金额本身是**权威必填**（ADR-022），折扣只是一个"帮我算金额"的快捷方式，业务人员实际都是直接填金额；
2. **两套真相**：折扣率与手填金额可能不一致（改金额清 rate、改数量重算等分支多，是历史多起金额问题的源头，见 BUG-06/BUG-25/BUG-27）；
3. **角色差异已被砍过一轮**：ADR-037 已把折扣入口对生态人员下线，现在只剩商务/管理员在用，实际使用率极低；
4. 审核页仍保留「折扣率快照」只读列，功能下线后该列必然恒为「-」。

## Decision
1. **前端全部移除**：
   - 购物车：折扣输入框、折扣摘要提示行、金额 placeholder 的折扣预计预览、顶部提示条里的折扣说明、`discountDrafts` 及相关函数一律删除；
   - 审核页（`sales/projects/review.vue`）：删除「折扣」只读列与 `discountRateText`，网格列宽重排；
   - 金额输入框 placeholder 固定为「必填，整数元」。
2. **后端容忍但不使用**：
   - `cart_items.discountRate` / `project_items.discountRate` / `contracts` 相关列**保留**（存量数据与历史项目快照不删，可追溯）；
   - `PUT /cart/{id}`、`POST /cart/checkout`、`POST /projects/{id}/review` 等入参**不再读取/校验/写入** `discountRate`（传了就忽略，不报错，避免旧客户端 400）；
   - 后端返回体可继续带该字段（存量只读展示用），但新单恒为 `null`。
3. **金额口径不变**：`amount` 仍是唯一权威；`salePrice × qty` 只做参考提示，不参与计算。

## Consequences
- **变容易**：购物车少一列输入、少一类校验分支；金额口径只剩一条路径（填多少就是多少），历史那批"折扣 × 数量覆盖金额"的坑彻底消失。
- **变难**：失去"按折扣快速算金额"的便捷（业务已确认不需要）；审核页少一个参考维度（历史单仍可从数据库/旧快照查到）。
- **可逆性**：**高**。回退 = 恢复前端控件 + 后端重新读取该列；无 schema 变更、无数据迁移。
- **影响面**：`cart/index.vue`（主）、`review.vue`（只读列）、`api/index.ts`/`types.ts` 类型注释、后端 4 处入参处理。
