# ADR-048: 金额精度放开到 6 位小数（展示最少 2 位、尾随 0 截断）

## Status

Accepted（2026-10-29，业务拍板：全量页面与销售明细价格支持多位小数；展示「最少两位，尾随 0 截到两位」）

部分取代 [ADR-008](ADR-008.md) / [ADR-022](ADR-022.md) 中的「金额须为整数元」条款；ADR-006「金额单位 = 元」不变。

## Context

ADR-008（包量计价）与 ADR-022（购物车行金额必填）把销售金额口径定为**整数元**，前端在输入框里用 `replace(/[^\d]/g, '')` 直接吃掉小数点，后端用 `amt != amt.to_integral_value()` 400 兜底。

实际业务中成交价常带小数（折扣分摊、按量/按 Token 折算、按面积/公里计价、尾差调整），强制取整导致下单人只能改数量或线下备注，金额与真实合同不符。用户要求：金额支持多位小数，展示时「最少两位、尾随 0 截到两位」。

## Decision

1. **精度上限 = 6 位小数（1e-6 元，微元级）**
   - 前端输入超过 6 位小数时**截断**（不是四舍五入），后端对直连接口超过 6 位返回 400；
   - 选择 6 位而非无限位的理由：① 派生单价 `_derived_price` 早已按 6 位量化；② SQLite 列是 REAL（双精度），6 位小数在常规金额量级（< 1e9）下往返无失真，再放宽会出现「入库值与输入值不等」。
2. **展示规则（全站统一）**：最少 2 位、最多 6 位，**去掉尾随 0 但至少保留 2 位**：
   - `12.5 → 12.50`、`12.3400 → 12.34`、`12.345678 → 12.345678`、`1000 → 1,000.00`；
   - 千分位保留；**不再四舍五入隐藏小数**（原 `Intl.NumberFormat` 的 `maximumFractionDigits: 2` 会把 12.3456 显示成 12.35，与落库值不符，本次改掉）。
3. **计算口径**：所有金额一律 `Decimal(str(x))` 计算，量化到 `1e-6`；取消「强制量化到分（`CENT`）」的金额落库/汇总写法，改为**同精度求和**，保证：
   - 行金额 = 用户输入值（≤6 位小数）；
   - 合同金额 = Σ 行金额（同精度，不再出现「Σ明细 ≠ 合同金额」的 400）；
   - 项目金额 / 看板 / 流水 / `soldAmount` 等派生值同口径。
4. **适用范围**：所有金额与单价输入——购物车行金额、销售建单（单价 / 包量金额 / 合同金额）、审核改价（实际单价 / 销售金额）、产品登记（销售单价、参考价格区间）、遥感明细单价（元/份）、交付补录金额。
5. **业务规则保持不变**：行金额必填、参考区间校验（viewer 仅下限）、按（产品, 客户）分组、库存锁定/释放、审批流转、服务期限选填口径，全部不动。**本次只改精度，不改任何业务语义分支。**
6. **无 DB 迁移**：金额列本就是 `Float`，读写边界仍是 `float ↔ Decimal(str)`。

### 展示函数实现要点
- 新增/改造 `formatMoney`、`formatYuan`、`derivedUnitPrice`（`frontend/src/types.ts`）：手工拼接「千分位整数 + 裁剪后小数」，不用 `Intl` 的 `maximumFractionDigits`（会舍入）。
- 输入组件（`el-input-number`）用 `:formatter` / `:parser` 实现「聚焦时原文、失焦后两位起展示」；`parser` 内截断到 6 位小数。不设 `:precision="0"`（会禁止小数），也不设 `:precision="6"`（会强行补 6 位零）。

## Consequences

- 变容易：成交价可以按真实值录入（折扣分摊、尾差、折算价），不再被迫取整；Σ明细与合同金额天然一致。
- 变难 / 需注意：
  - 财务报表、导出、看板可能出现 3~6 位小数，用「分」对账的场景需按 6 位四舍五入后再取两位；
  - 金额列宽需复核（列表小计列原按「¥ + 最多 17 字符」设定）；
  - 前端 JS 合计（`totalAmount` / `previewGroups` / 合同合计）必须先按 1e-6 规整再累加，避免浮点尾巴。
- 可逆性：**中**。校验/量化/展示三处口径需同时回退，否则会出现「能输入但入库被截」的错配。
- 存量数据：整数金额天然满足 ≤6 位，无需回填。

## 验证

1. 后端：`python3 -m compileall -q src main.py`；Decimal 边界（6 位通过 / 7 位 400 / 0 / 负数）；副本库跑一遍「加购 → 填 2/3/6 位小数金额 → 结算 → 审核改价 → 交付」，校验 `project_items.amount`、`contracts.contractAmount`、`projects.expectedAmount` 三处相等。
2. 前端：金额输入用例（`12.3456789 → 12.345678`、`12.3400 → 12.34`、`12.5 → 12.50`、`12. → 12.00`）；全站 `formatMoney` 抽查列表/详情/看板/弹窗。
3. 回归：参考区间校验、viewer 仅下限、分组拆合同、库存锁定/释放、审核驳回释放、服务期限成对校验——行为与改动前一致。
