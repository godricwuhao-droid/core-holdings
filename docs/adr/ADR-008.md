# ADR-008: 卫星 Token 类资产采用包量定价（pricingMode='amount'，合同金额整数元权威）

## Status
Accepted（2026-10-16）

## Context
卫星 Token 资产以原始 Token 个数计库存（如 3 亿 = 300000000）。按现行计价规则 `amount = price × qty`（后端权威重算）：
- 3 亿 Token 卖 1000 万元 → 单价 = 0.0333... 元/Token，无限循环小数，无法精确存储；
- 部分售卖（如 1.37 亿）按单价乘出的金额不是整数，与"合同金额必须整数元"的财务口径冲突。

问题本质不是精度不够，而是 **Token 资产的计价模型不是单价制**——客户购买的是资源包（"3 亿 Tokens，1000 万元"），单价只是谈判参考值。

## Decision
新增 `Asset.pricingMode` 字段：`'unit'`（默认，单价×数量）| `'amount'`（包量金额权威）。

1. **字段**：`assets.pricing_mode` VARCHAR(16) 默认 `'unit'`（幂等迁移补列）；卫星 Token 类型资产入库时置 `'amount'`。显式字段而非按类型硬编码，为未来"算力服务期"等同类资产预留。
2. **资产单价**：`'amount'` 模式下 `salePrice` 仅作参考值，按"元/万Token"口径展示（如 ¥3.33/万Token），**不参与任何金额计算**。
3. **销售明细**：`'amount'` 模式下明细行以 **合同金额（整数元，后端校验 `int > 0`）为权威输入**，`price = amount / qty` 仅作派生展示值（存 6 位小数，展示带"约"）；后端**跳过** `price × qty` 权威重算。
4. **合同金额**：`contractAmount = Σ 明细金额`，天然整数，无舍入误差。
5. **库存**：锁定/出库/回滚仍按 Token 原始个数计，与计价无关，零改动。
6. **数量展示**：库内仍存原始 Token 数，展示层新增 `formatTokens`（300000000 → "3 亿"，137000000 → "13700 万"）。
7. **购物车**：`'amount'` 模式行在购物车中需输入合同金额（整数元），结算直接生成合同。
8. **金额口径**：全程"元"（前端/后端/数据库），不引入万元口径（既有约定，本次重申）。

## Consequences
- 变容易：合同金额零误差、与"资源包售卖"现实业务一致、库存体系零改动；未来算力板块可直接复用 `'amount'` 模式。
- 变难：Token 资产的"可售金额"统计失去精确意义（`availableValue` 对 `'amount'` 模式显示参考值或不显示）；同一资产不同合同单价可以不一致（真实业务，但报表需按合同维度看）；购物车/下单弹窗/项目创建三处明细 UI 需增加 amount 模式分支。
- 可逆性：**高**——仅加列 + 计价分支，回退忽略该列即可，`'unit'` 模式行为完全不变。
