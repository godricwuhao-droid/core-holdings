# ADR-026: 生态人员「撤销」待审核订单（终止 + 明细回填购物车）

## Status
Accepted（2026-10-21，业务要求：生态人员提交的待审核销售项目缺少撤回能力；按钮名「撤销」）

## Context
生态人员（viewer）下单后项目进入 `pending`（锁定已占用），目前只有「取消订单（终止）」——终止即终点，要改单只能人工重填，且无原因留痕。业务需要一个新的「撤销」动作：把待审核订单撤回、释放锁定、并让下单人可以直接改单重提，同时全程留痕。

现有可复用机制：
- 终止链路：合同 `pending → terminated`（`_change_contract_status_core`）逐明细释放真实锁定（`it.locked`）+ `cancel_release` 流水，项目派生为 `terminated`；
- 购物车加购核心 `_cart_add_inner`：判重键 `(userId, assetId, itemId, customer)`、存在即累加、金额/服务期限/折扣率全套校验；
- 建单人与负责人：`Project.creator`（username）与 `Project.businessOwner`。

## Decision
1. **语义**：`撤销 = 终止原单（释放锁定、留痕）+ 全部明细自动回填下单人购物车`（保留客户/数量/金额/服务期限/折扣率/遥感明细 itemId），用户在购物车调整后重新结算提交。原单保留为 `terminated` 历史（可查原因），不删除、不新增「草稿」状态。
2. **新端点** `POST /api/projects/{id}/withdraw`，body `{"reason": "必填，1–200 字"}`，`require_order` 守卫：
   - 权限：`creator == 登录 username` 或 `role == admin`（存量 creator 为空时回退 `rep` 匹配姓名/username）；否则 403；
   - 前置：仅 `status == 'pending'` 可撤销，否则 400「仅待审核订单可撤销」；
   - 原因必填，空白 400「请填写撤销原因」；≤200 字，超长 400；
   - 有 `businessOwner` 时自动**解绑**（置空）并留痕。
3. **事务一致性**（单事务）：① 逐合同 `pending → terminated`（复用 `_change_contract_status_core`，内部释放真实锁定 + 写 `cancel_release` 流水 + 合同 remark 追加「撤销：{reason}」）；② 项目置 `terminated` 并重算派生金额；③ 解绑负责人；④ 按合同 `customer` + 明细 `assetId/itemId/qty/amount/serviceStart/serviceEnd/discountRate` 逐行调用 `_cart_add_inner` 回填下单人购物车；⑤ 写 OpLog（`撤销订单`）+ 审计。
4. **回填容错**：某行因参考区间/可售上限/数据缺失无法回填时，**不中断撤销**——该行降级为「原价成交/跳过」并在响应 `skipped/amountFallback` 中返回，前端 toast 提示具体行数与原因类别（避免撤销被单行数据卡死）。
5. **前端三处入口**（`pending` 且本人或 admin 可见）：项目列表行操作、项目详情页头部、编辑页底部（替换 pending 状态下的「取消订单（终止）」，非 pending 的终止能力保留）；点击弹「撤销订单」对话框，必填原因；成功后 toast 提示并把用户带到 `/cart`（下一步就是改单重提）。
6. **不改现有终止/驳回/重新提交口径**：`PATCH /projects/{id}/status`（terminated）、`POST /projects/{id}/review`（reject）、`POST /projects/{id}/resubmit` 行为不变。

## Consequences
- 变容易：生态人员自助改单闭环（撤销 → 购物车 → 重新提交）；锁定与流水复用既有终止链路，无新增状态；撤销原因可查（合同 remark + OpLog + 审计）。
- 变难：撤销动作跨「项目/合同/明细/产品锁定/流水/购物车」多表，必须单事务；回填需处理判重合并与区间校验降级（已在 Decision 4 定义）；管理员代撤销时购物车归属下单人，需要 username → userId 映射校验。
- 可逆性：**中高**。新增端点与前端按钮可随时下线；数据面撤销只写既有字段（status/remark/businessOwner + 购物车行），无 schema 变更。
