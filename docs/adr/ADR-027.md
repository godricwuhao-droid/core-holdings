# ADR-027: 「重新提交」统一收口购物车（回填幂等）+ 移除 create 页 copy 模式

## Status
Accepted（2026-10-21，业务要求：终止项目点「重新提交」应进购物车改单，不再进编辑页）

## Context
终止项目（撤销/驳回）的「重新提交」目前跳 `/sales/projects/create?copy={id}`——复用编辑页预填原单明细后调 `POST /projects/{id}/resubmit` 新建订单。业务认为该路径绕：撤销已经把明细回填进购物车，用户更希望「重新提交」直接进购物车改单再结算，与撤销后的动线一致。同时 copy 模式是 create 页的第二套形态（预填/校验/提交分支），维护成本高且仅两处入口。

`create.vue` 同时承载 `/sales/projects/create`（新建）与 `/sales/projects/:id/edit`（编辑），**页面不可删除**，只能移除 copy 模式。

## Decision
1. **「重新提交」= 确保明细在购物车 → 跳 `/cart`**：
   - 新端点 `POST /api/projects/{id}/refill-cart`（`require_order`）：仅 `terminated` 项目；权限与 resubmit 同口径（下单人本人 / admin / editor）；把明细回填**下单人**购物车（客户/数量/金额/服务期限/折扣率/遥感 itemId，复用 `_cart_add_inner`）。
   - **幂等只回填一次**：`Project.cartRefilled`（bool，默认 False）标记——`withdraw_project` 回填后置 True；本端点见 True 直接返回 `alreadyRefilled: true` 不重复回填（避免同一明细在购物车翻倍）。
2. **一次性迁移**：`projects.cartRefilled` 补列（幂等 ALTER），并把**已撤销过**的历史终止项目置 True（判据：其合同 remark 含「撤销」），防止老数据被二次回填；被驳回的历史项目保持 False（首次点重新提交才回填）。
3. **前端**：列表行与详情页「重新提交」改为调 refill-cart → `refresh()` → `router.push('/cart')`；`alreadyRefilled` 时提示「明细已在购物车」。
4. **移除 create 页 copy 模式**：删 `?copy=` 分支（预填、canSubmit 的 copy 放行、copy 标题、resubmit 提交分支、隐藏保存草稿的 copy 判断）与路由守卫中 viewer 的 copy 放行；页面仅保留新建/编辑。
5. **后端 `POST /projects/{id}/resubmit` 保留**（无前端入口），docstring 标注 deprecated，避免影响任何既有调用/脚本；`ProjectOut` 增加 `cartRefilled` 供前端判断提示文案。

## Consequences
- 变容易：终止项目改单动线唯一（购物车），与撤销一致；create 页少一套形态，回归面变小；重复回填有幂等标记保护。
- 变难：新增一列 + 一次数据迁移（历史撤销项目判据依赖 remark 文本）；refill 与 withdraw 共用回填逻辑，需保持两处口径一致；resubmit 端点成为无入口遗留（已标废弃）。
- 可逆性：**高**。前端入口改动可回退；`cartRefilled` 为纯增量列，refill 端点可下线；resubmit 未被删除，如需恢复 copy 模式可原样接回。
