# ADR-019: 关键时间节点与状态机扩展（合同签订时间 / 预计交付时间 / 进行中→交付中）

## Status
Accepted（2026-10-20，业务已拍板：按合同独立触发、全部签完项目才「交付中」、交付前 signedDate 必填）

## Context
现状状态机：合同 pending→active→delivered（delivered 一步完成扣量+流水+交付记录），无「交付中」；项目状态由合同派生（pending/active/delivered/terminated）；合同无签约时间字段（项目级只有预计签约 expectedSignDate）；无预计交付时间字段；`ProjectItem.confirmedDate` 为死字段。

业务要求的时间节点：下单时间（=项目创建时间，仅展示）、合同签订时间（商务填，填完合同进入交付中）、预计交付时间（管理人员在交付中状态填）、服务期限（见 ADR-020）。

## Decision
1. **新字段**：`contracts.signedDate`（合同签订时间，商务填）、`contracts.scheduledDeliveryDate`（预计交付时间，**仅 admin** 填，合同 delivering 时录入）；下单时间不新增字段，展示用项目 `createdAt`（合同卡现有"签约/锁定=lockedDate"改名为"下单时间"）。
2. **合同状态机**：`pending → active（合同签订中）→ delivering（待交付）→ delivered`，terminated 各阶段可达（现有释放锁定/撤销交付语义保留）：
   - 合同录 `signedDate` 即 `active → delivering`（新端点 `PATCH /contracts/{id}`，editor/admin；录后**可修改、不可清空回退**）；
   - `active → delivered` 的交付动作**禁止**：合同必须先 delivering（signedDate 非空），否则 400；
   - **扣量/流水/交付记录仍在 `delivering → delivered` 时发生**（进入 delivering 不扣量）。
3. **项目派生**（`_derive_project_status` 扩展）：
   | 合同集合 | 项目状态 |
   |---|---|
   | 全 pending | pending（待审核） |
   | 全 delivered | delivered（已完成） |
   | 含 terminated 且其余全 pending/terminated | terminated |
   | 全部合同均 ≥ delivering（即全部已签，含已交付） | **delivering（交付中）** |
   | 其余（含 active 未签完） | active（进行中） |
4. **权限**：录 signedDate = editor/admin（接手人守卫与审核同口径：仅该单商务负责人/admin）；录 scheduledDeliveryDate = **仅 admin**（系统"管理人员账号"= admin 角色）；状态中文新增「交付中」。
5. `PATCH /contracts/{id}` 入参：`{ signedDate?: "YYYY-MM-DD", scheduledDeliveryDate?: "YYYY-MM-DD" | null }`，可分别校验角色；清空 scheduledDeliveryDate 允许（可纠正），清空 signedDate 拒绝（400）。

## Consequences
- 变容易：合同签订/交付等待期有明确状态与时间可追踪；交付前置签约符合业务流。
- 变难：派生逻辑变复杂（`_derive_project_status` / `_recompute_project` / 合同状态白名单 / 撤销交付回退路径都要扩展——撤销 delivering 合同的交付后合同应回 delivering 而非 active，因 signedDate 仍在）；存量 active 合同无 signedDate，交付入口会被新守卫拦——**存量数据需在上线时由商务补录签订时间**（当前库 active 合同仅 1 单，人工处理）。
- 可逆性：中高。状态值为字符串，代码 revert 即恢复；但已进入 delivering 的合同在旧代码下会显示为 active（语义漂移），回退前建议无 delivering 合同。
