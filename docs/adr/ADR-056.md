# ADR-056: 销售项目列表排序 / 详情页勾选驳回订单 / 产品统计页（按主体）

## Status
Accepted（2026-11-04，已实现 + QA 独立回归全绿：§1 列表 5 列服务端排序（status 生命周期档位 + 金额/日期/编号，`id.desc()` 兜底、10 组合翻页无重复/遗漏、三次点击回最新）；§2 详情页合同列表勾选/单一驳回（仅 pending，部分驳回项目保持 pending 可续审、全驳→terminated、`_derive_project_status` 补 `[terminated,pending]→pending` 分支、11 项守卫 403/400/422 全对、下游锁定精确释放 + 遥感明细回 in_stock、不动 shipped/sold）；§3 产品统计页（按 `Asset.subject` 主体聚合 7 主体×5 指标与手工求和逐值相等、可展开对账、采购口径、viewer 不可见/finance 放开可见、/assets 只读不回归），无阻断缺陷）

## Context
用户要求 3 处：
1. **销售项目列表（`/sales/projects`）加排序**：「项目状态」列按状态排序，且状态+销售金额+最近跟进+预计签约+项目编号都可排序。
2. **审核支持勾选订单驳回**：在**销售项目详情页**以**列表形式**呈现订单，支持**勾选多个驳回**或**单一驳回**（例：一个项目 4 个合同，勾选 3 个驳回、剩余 1 个保持可审）。仅对**待审核(pending)** 合同。
3. **新增「产品统计」一级菜单页面**：**按主体（产品所在主体 = `Asset.subject`）呈现资产数量**，用于和 Excel 库存明细对账；**仅生态人员(viewer)不可见**，admin/主管/商务/财务可见。

现状（code-explorer 摸底）：
- **列表**（`views/sales/projects/index.vue`）已服务端分页（ADR-055，`GET /projects` api.py L264-313，`order_by(id.desc)`）。状态列渲染**派生 `projectOutcome`**（8 文案）但存 `status` 仅 5 值（pending/active/delivering/delivered/terminated，terminated 细分靠日志/remark，纯展示）。**全前端 0 处 `sortable`**。
- **审核**：`POST /projects/{id}/review`（api.py L512-528）→ `review_project`（services.py L2458-2745）**整项目粒度**（reject 遍历全部合同 L2507-2529）。**Contract 无独立 rejected 态**——驳回 = `terminated` + remark `驳回：` 前缀 + 日志 `驳回订单`（ADR-041 展示口径）。详情页 `detail.vue` 合同是**卡片列表**（L496-670，`db.contracts` 按 projectId 过滤 L146-149）。驳回下游：释放锁定 `_apply_item_release`、遥感明细回 in_stock `_sync_rs_item_statuses`、项目 `_recompute_project` 派生；不动 shippedQty/soldAmount/购物车。
- **统计**：`Asset.subject`（models.py L21，我司签约主体，源 `Entity` 表）；**无供应商字段**。聚合可照抄前端 `getDashboard().boardStats`（api/index.ts L414-427，把 `board` 换 `subject`），数据全在 bootstrap `db.assets`。路由/菜单/守卫见 router/index.ts L16-112 + MainLayout.vue L53-127（菜单 `v-if` 控角色）+ 守卫 L166-208（viewer/finance 收窄白名单）。

## Decision

### §1 列表排序（服务端）
| 项 | 决定 |
|---|---|
| **可排序列** | 「项目状态」「销售金额」「最近跟进」「预计签约」「项目编号」5 列 `sortable="custom"`（服务端排序） |
| **排序键** | `status`（按**状态档位**排，非字符串）/ 销售金额(列显示字段)/ 最近跟进`lastFollowDate` / 预计签约`expectedSignDate` / 编号`code` |
| **状态排序档** | 生命周期序 `pending(0)→active(1)→delivering(2)→delivered(3)→terminated(4)`；terminated 三子型(已撤销/已驳回/已终止)同档聚排（与 status 过滤一致） |
| **参数** | `GET /projects` 加 `sortBy?`（`status`/`amount`/`lastFollowDate`/`expectedSignDate`/`code`）+ `sortOrder?`（`asc`/`desc`）；缺省不传 → 保持 `id.desc()`（最新在前） |
| **分页稳定** | 排序键后**恒定 `id.desc()` 兜底**（同值行稳定，避免翻页重复/丢行） |
| **status 过滤** | 不变（仍按存 `status`，api.py L301-302） |

### §2 详情页勾选驳回（仅 pending 合同）
| 项 | 决定 |
|---|---|
| **入口** | **详情页 `detail.vue`** 把合同展示改/增为**列表(表格)形式**（合同编号/客户/签约主体/金额/状态/下单时间 + 操作列），**项目 `pending` 时**合同行可勾选（`el-table` selection）+ 顶部「**批量驳回**」（≥1 选中启用）+ 行内「**驳回**」（单一） |
| **范围** | 仅**待审核(pending)** 合同可驳回；一个项目勾选 N 个驳回后，**剩余 pending 合同项目保持 pending 可继续审核**；已确认(active/delivering)合同仍走原「终止」，不受影响 |
| **后端** | 新增 `POST /api/projects/{id}/reject-contracts`，body `{ contractIds: int[], reason: str }`；**复用** `review_project` reject 的**逐合同**步骤（`_apply_item_release` 释放锁定 → `c.status="terminated"` → remark 追加 `驳回：{reason}` → `_sync_rs_item_statuses` → `_recompute_project` → `add_log("驳回订单")`），仅对选中合同；建议把该逐合同逻辑抽 helper 供 review/reject-contracts 共用 |
| **驳回状态** | **复用 `terminated` + remark `驳回：` 前缀**（零迁移，ADR-041 展示层天然细分「已驳回」） |
| **原因** | 必填（同现状）；批量勾选**共用一个原因** |
| **项目状态** | 驳回后 `_recompute_project` 从剩余合同派生：**仍有 pending 合同 → 项目保持 pending**；**全部驳回 → terminated**（需 backend 验证 `[terminated×N, pending×M] → pending` 派生正确） |
| **鉴权** | `require_editor`（admin/supervisor/editor）+ 接手人守卫（同 review L2492-2498） |
| **review 页** | 现有「整单驳回」保留（reject-all 有效路径），与新「勾选驳回」并存 |

### §3 产品统计页（按主体，纯前端）
| 项 | 决定 |
|---|---|
| **分组键** | **`Asset.subject`（产品所在主体）**；空 subject 归「(未设主体)」（不隐藏） |
| **数据** | bootstrap `db.assets` 全量，**前端聚合**（照抄 `getDashboard().boardStats`，`board`→`subject`）；**无后端新端点** |
| **页面** | 新增 `views/statistics/index.vue`：主体**汇总表**（主体/产品数/总数量/剩余量/剩余金额/采购总价）+ **可展开到单个资产明细**（编号/名称/数量/剩余量/剩余金额/采购单价/采购总价/销售状态）——支撑"按主体呈现" + "逐条对账 Excel" |
| **口径** | **采购口径**：采购单价=`salePrice`、采购总价=`quantity×salePrice`、剩余量=`availableQty`（复用 types.ts，遥感容器用后端 `availableCount`）、剩余金额=`剩余量×salePrice`、销售状态=可售/售罄（`in_stock`/`all_sold`） |
| **路由** | router children 加 `statistics`（`/statistics` → `views/statistics/index.vue`） |
| **菜单** | MainLayout 加一级菜单「产品统计」，`v-if="!isViewer"`（admin/主管/商务/财务可见） |
| **守卫** | viewer：`viewerAllowedPath` 不含 `/statistics` → 自动拦回；**finance：`financeAllowedPath` 增加 `/statistics`**（放开让其能看） |

## Consequences
**变容易**：项目列表可按状态/金额/日期/编号排序；审核可精准驳回部分订单（不必整单）；有按主体的资产统计页对账 Excel。

**变难 / 风险**：
- **§1 排序 + 分页稳定**：必须恒加 `id.desc()` 兜底，否则同排序值行翻页会重复/丢行；status 必须按档位映射（非字符串序）。
- **§2 部分驳回派生**：需验证 `[terminated×N, pending×M] → 项目 pending` 派生正确（`_derive_project_status` 现多按"全部同态"设计，部分驳回是新增路径）；驳回逻辑要与 review 整单驳回保持一致（抽共用 helper）。
- **§2 详情页合同卡片→表格**：detail.vue 改动较大，须保留非 pending 合同的既有操作（交付/终止/录签订时间）。
- **§3 finance 放开**：`financeAllowedPath` 加 `/statistics` 后，确认 finance 菜单/守卫一致、不破坏 finance 只读 /assets。
**可逆性**：高——§1 加参数（向后兼容，缺省不变）；§2 新增端点 + 复用 terminated（零迁移）；§3 纯前端新页 + 菜单 + 守卫白名单。

## 任务拆分
- **backend-dev**：§1 `GET /projects` 加 `sortBy/sortOrder`（status 档位映射 + 金额/日期/code，`id.desc()` 兜底）；§2 新增 `POST /projects/{id}/reject-contracts`（复用逐合同驳回逻辑，验证部分驳回项目派生）。自测含：各排序键 + 翻页稳定、status 档位序；部分驳回（4 合同勾 3 → 剩 1 pending、项目仍 pending、3 个已驳回、锁定释放、可继续审剩 1）、全部驳回→terminated、鉴权/接手人守卫、原因必填。
- **frontend-dev**：§1 列表 5 列 `sortable="custom"` + `@sort-change` + 传参；§2 详情页合同改列表(表格)+selection+批量/单一驳回；§3 新增统计页(主体汇总+资产明细展开)+菜单+路由+finance 守卫。`vue-tsc` 0。
- **QA**：三处 + 护栏（排序翻页稳定/状态档位、勾选驳回部分/全部/继续审剩/已确认合同终止不受影响/下游数量、统计页按主体聚合正确/对账列/五角色可见性 viewer 拦 finance 可看/finance 只读产品不回归）。
