# ADR-066: 业务一致性修正 + 交付数据域收口 + 遥感下架

## Context
ADR-065（卫星Token 计价归一）之后，对**计价/结算、项目状态机、合同金额对账、交付/出库、权限/数据域、遥感数据**六域做了**全面只读业务逻辑 BUG 排查**。核心不变量大多核对无误（unit 金额=单价×数量 全入口、超区间硬拦全结算入口、`contractAmount==Σ project_items.amount` 全改价入口、`expectedAmount==Σ contractAmount`、状态派生 `_derive_project_status`+`_recompute_project` 覆盖完整、`pending_assign` 守卫一致、数据域 `build_visibility` 实时预计算、rs 计价/售罄护栏/容器数量派生），但发现 **3 个确认的高 bug** + **2 处需业务拍板的一致性/权限问题**；同时用户提出**遥感类型简化**（先下架、后续重新设计，当前只保留"普通商品"一种逻辑）。

## Decisions（用户拍板 2026-11-10）

### 1. 撤单语义（withdraw）＝只撤 pending 合同
撤销 `pending`/`pending_assign` 项目时，**只终止其中 `pending` 的合同**；已确认/已交付（`active`/`delivering`/`delivered`）合同**保留不动**。
- 项目**剩余非 pending 合同** → 保留负责人、状态按剩余合同 `_recompute_project` 派生（通常为 `active`/`delivering`，**非整单 terminated**）；
- 项目**无剩余非 pending 合同**（全 pending 被终止）→ 整单终止（解绑负责人 + `terminated`，维持现状行为）；
- **撤单回填购物车**只回填**被终止的 pending 合同**对应明细（保留的合同不回填）。
- 现状 bug：`withdraw` 循环终止**全部**合同，与 docstring「逐合同 pending→terminated」及业务意图不符。

### 2. 交付数据域守卫（收紧）
`editor`（商务）交付/终止/撤销交付**仅限自己名下**（`user_sees_project` 为真，即 `businessOwner==自己`）的项目，他人单 403；`admin`/`supervisor` 越过。
- 涉及 4 处缺守卫的函数：`change_contract_status`、`change_project_status`、`create_outbound`、`revert_outbound`（`review`/`claim`/编辑 pending 均已有归属守卫，交付链路独缺）。
- 与整体数据域口径一致（`user_sees_project` 唯一口径），堵住 editor 持 id 越权操作他人单。

### 3. 遥感数据：只下架（软处理）
代码/类型/`rs_items` 机制**全保留**，仅把存量 2 个「遥感数据」资产置**下架/不可售**（不再进可售/下单入口）；后续重新设计时再动代码。存量 5 项目/8 订单行/61 明细不受影响、仍可结算交付。

### 4. 三处高 BUG 修复
- **#1 回填购物车**（`_refill_cart_from_project`，services.py:1491）：unit 行误把「行总额」`it.amount` 写进购物车「单价」字段 → 再结算 `总额×qty`（×qty²）多收。改为回填 **`it.price`（单价）**；rs/amount 语义行（qty≡1 或总额）保持 `it.amount`。
- **#2 撤销交付 rs 口径**（`_revert_outbound_inner`，services.py:3378-3382）：rs 明细行撤销用**容器** `a.repeatSale`（ADR-036 强制恒 false）而非**行级** `_item_repeat` → `repeatSale=1` 的 rs 行撤销时容器 `shippedQty` 漂移/500。改为与交付侧（services.py:2065）同口径 `eff_repeat = _item_repeat(db, a, it.itemId)`；`projectItemId` 为 NULL 的 legacy 回退路径保留。
- **#3 ADR-064 回填范围**（main.py:416-433）：对**全部**项目 `_recompute_project` → **无合同**的 `terminated`/`delivered` 项目被覆写成 `active` + 金额清零。改为**只处理有合同的项目**（无合同项目跳过、保留原状态）。**迁移前必修**（旧生产库可能有无合同项目，会命中此覆写）。

## Consequences
- **撤单**：部分确认后撤销更保守（保留已确认部分），符合"撤销=撤未确认"直觉；项目状态从 `pending` 回到 `active`/`delivering`（非整单 terminated）。
- **交付数据域**：editor 不能再互操作他人单（协作需经 admin/supervisor）；与整体数据域口径一致。
- **遥感下架**：零代码改动，存量 5 项目不受影响，后续重设计时机制保留可复用。
- **#3** 对 dev 无影响（该迁移已跑、0 条命中）；对**旧生产库迁移**关键（无合同项目不再被覆写）。
- **#1/#2** 为潜伏 bug（dev 当前无触发数据：无"unit qty>1 撤销/回填"、无"repeatSale=1 的 rs 行"），修复防旧库/未来数据命中。

## 可逆性
- 撤单 / 交付数据域：可逆（改回即恢复）。
- 遥感下架：可逆（重新上架即可）。
- #1/#2：可逆（代码改回）。#3：可逆（代码改回；已迁库需清 marker 重跑才影响）。
