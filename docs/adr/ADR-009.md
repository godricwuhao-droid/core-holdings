# ADR-009: 购物车按登录用户隔离 + viewer 下单链路权限前后端对齐

## Status
Accepted（2026-10-16）

## Context
1. **购物车 userId 未接通**：`cart_items.userId` 列、schema 字段、services 全部函数 `user_id` 参数、`(userId, assetId, customer)` 判重均已预留，但 router 层一律传 `DEFAULT_USER = "admin"`（`api.py:277` 注释"本轮不按登录用户隔离"）。多角色使用时：viewer 能看到/改/删 admin 加的行，admin 结算会把他人加的行一起清掉——数据串扰与隐私问题。
2. **viewer 权限前后端脱节**：后端 `/cart`、`/cart/batch`、`/cart/{id}`、`DELETE /cart`（清空）、`checkout` 已全部改为 `require_order`（认证即放行，viewer 可用），但前端购物车"清空"按钮仍 `:disabled="!canWrite"`（viewer 被禁），资产列表 `batchAddToCart` 保留 `isViewer` 逐条单加降级分支及"后端仅 admin/editor"过期注释。

## Decision
1. **购物车按登录用户隔离**：router 层购物车全部端点将 `get_current_user` 的 `user.id` 传入 services，删除 `DEFAULT_USER` 传参（常量保留仅供 seed/兼容）；`bootstrap` 返回的 `cart` 仅包含当前用户行。前端购物车页面、菜单角标自动跟随（数据源不变，仍读 `db.cart`）。
2. **权限矩阵对齐（以"下单链路 = 认证即可"为准）**：
   - 前端购物车"清空"按钮对 viewer 解禁：判据由 `canWrite` 改为 `state.user !== null`（已登录即可，与后端 `require_order` 一致）；
   - 删除 `batchAddToCart` 中 `isViewer` 逐条降级分支，三角色统一走 `POST /cart/batch`；删除过期注释。
3. 结算 `checkout` 仅清空**当前用户**的购物车行（隔离后天然成立，无需额外代码）。

## Consequences
- 变容易：多账号并存下购物车互不干扰；前后端权限矩阵单一事实来源（下单链路=require_order）；删除一处冗余分支代码。
- 变难：存量数据 `userId='admin'` 的购物车行在切换后仅 admin 可见（演示数据，可接受）；viewer 权限行为变化需回归验证（清空/批量加购/结算）。
- 可逆性：**中**——数据层已隔离，回退只需 router 重新传 `DEFAULT_USER`，但已产生的按用户分桶数据需手工合并。建议视为"账号权限管控"路线图的正式第一步。
