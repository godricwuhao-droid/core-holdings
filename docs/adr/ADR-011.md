# ADR-011: 遥感数据改「父资产 + 可售明细」两层模型（省×精度×月份）

## Status
Accepted（2026-10-16）**Supersedes ADR-010**

## Context
ADR-010 落地后被业务方纠正：遥感数据不应"每个 省/精度/日期 组合 = 资产列表独立一行"，而是：
- **资产列表里是 1 个总资产**（父资产，type=遥感数据）；
- 点开/加购时才展开其下的**明细可售卖资产**，维度为 **省（可含市）× 精度 × 月份（YYYY-MM）**；
- 真正售卖的是明细：每份明细一个单价（整数元/份），**默认可重复售卖、只计次不扣量**。

用户确认：第三维度以**月份**为准；已建的演示资产（河北省石家庄市 1.5m 2026-09-15，id 动态）直接删除。

## Decision
1. **父资产**：`assets` 表 type='遥感数据' 行仅做容器，本身不可直接加购/下单；`quantity/lockedQty/shippedQty` 对父资产无意义（展示" N 份明细"）。ADR-010 给 assets 加的 4 列（province/city/resolution/imageDate）**废弃**（列保留不删，schema 移除，代码停用）。
2. **明细表** `rs_items`（新表，camelCase 列名与全库一致）：
   | 列 | 说明 |
   |---|---|
   | `id` / `assetId` | 主键 / 父资产 id |
   | `province` | 省/自治区/直辖市，必填 |
   | `city` | 市，可空（默认 `''`） |
   | `resolution` | FLOAT，精度（米），如 1.5 |
   | `saleMonth` | VARCHAR(7)，YYYY-MM，必填 |
   | `price` | FLOAT，单价（**整数元/份**），必填 > 0 |
   | `repeatSale` | BOOL 默认 `true`（可关闭） |
   | `createdAt` / `updatedAt` | 时间戳 |
   唯一性：`(assetId, province, city, resolution, saleMonth)` Python 层判重（与全库风格一致），重复 400「该父资产下已存在相同 省/市 + 精度 + 月份 的明细」。
3. **接口**（均 `require_editor`，admin/editor 可维护；读随 bootstrap 放行）：
   - `POST /assets/{assetId}/rs-items`（RsItemInput：province/city/resolution/saleMonth/price）
   - `PUT /rs-items/{id}`（同入参，唯一性排除自身）
   - `DELETE /rs-items/{id}`：任一 `project_items.itemId` 引用该明细（含已完成合同）→ 400「该明细存在销售关联，无法删除」
   - `bootstrap` 快照新增 `rsItems: RsItem[]`
4. **购物车**：`cart_items` 加列 `itemId` INT NULL（挂 rs_items）。含 itemId 的行：数量恒 1（后端校验 qty≠1 → 400）；判重键 `(userId, assetId, itemId, customer)`；`CartItemOut.itemId` 输出。
5. **销售链路**：`project_items` 加列 `itemId` INT NULL；建项目/直接下单/购物车结算时，含 itemId 的明细行 **金额后端权威 = `rs_items.price × 1`**（忽略前端传值）；明细 `repeatSale=true` → 不锁定、不扣库存，交付/终止走现有 repeatSale 链路（计次）。`ProjectItemOut.itemId` 输出。
6. **前端交互**：
   - 新组件 `RsItemPicker.vue`：明细选择弹窗，`el-tree` 结构 **省 → 精度 → 月份**，叶子 checkbox + 单价展示；用于 ① 资产列表遥感数据行"加入购物车"（勾选 N 份 = N 行购物车，客户行内填）② 资产详情"登记销售"（勾选后进 SalesOrderDialog，订单级客户 + N 行明细）
   - 资产详情新增"**可售明细**"页签：明细表格（省/市 · 精度 · 月份 · 单价 · 已售次数 · 可重复售卖 · 编辑/删除）+ 新增/编辑明细弹窗；
   - 资产列表遥感数据行："资产总数"列显示"N 份明细"；名称列次级行显示明细数与覆盖省份摘要；
   - 资产新建表单：**移除** ADR-010 的三维字段组（遥感数据按普通父资产登记：名称/主体/备注等）；
   - 购物车：遥感行名称 = 父名 · 明细（省/市 精度 月份），数量禁用恒 1，单价 = 明细单价；
   - 项目创建/详情、合同明细表：增加"明细"列（查 rsItems 镜像展示）；
   - 移除 ADR-010 前端遗留：list 三维摘要次级行、detail 三维展示、create 三维字段组与本地判重。
7. **数据清理**：一次性幂等迁移删除演示遥感数据资产（名称"河北省石家庄市 1.5m 2026-09-15"）。
8. **计价模式**：遥感数据用标准 `'unit'` 模式（ADR-008 不受影响），金额天然整数元。

## Consequences
- 变容易：列表保持"1 个总资产"的清爽口径；售卖粒度细化到省/精度/月份且可重复售卖，交付/终止/回滚全部复用 repeatSale 现有链路；明细维度扩展（如加坐标区）只改 rs_items 不动 assets。
- 变难：引入第一张"资产子表"，cart_items/project_items 增加可空外键维度（判重、展示、回滚逻辑需感知 itemId）；Asset 上 4 个废弃列成为技术债（保留不删，schema 已清理）；前端 4 处页面 + 1 个新组件同步。
- 可逆性：**中**——rs_items 是新表，回退=停用接口+忽略 itemId 列，但已产生的明细/购物车/合同引用需人工清理；比 ADR-010 的回退成本高，因售卖数据已按明细粒度落库。
