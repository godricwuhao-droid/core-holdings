# ADR-040: 销售项目删除入口收敛至「更多▾」且仅管理员（Supersedes ADR-028 §3 的入口位置，护栏不变）

## Status
Accepted（2026-10-22，业务方在 A 全删 / B 收敛 / C 软删除 三案中选定 **B**）

## Context

1. **删除不是"删一行"**：`services.delete_project`（`backend/src/services.py:2675`）一次调用会——按合同回滚（`active/pending/delivering` 释放锁定、`delivered` 撤销名下 done 交付并回退 `shippedQty/soldCount/soldAmount`）→ 撤销挂项目的手动交付（`contractId == null`）→ 级联硬删项目/合同/明细 → 明细状态回 `in_stock` → 写 OpLog。这是**整套业务数据回滚**，风险等级与「删除产品」同级。
2. **入口却极廉价**：销售项目列表操作列（`width=220`）在 220px 里塞了「接手/转交、审核订单/编辑、重新提交、撤销、删除」5 类按钮，删除是常驻按钮，一次误点即触发上述回滚。
3. **护栏已存在但入口仍是死按钮**：ADR-028 §3 已规定 `terminated && cartRefilled`（撤销单）→ 403，前端也提前禁用。**2026-10-22 线上实测：项目总数 2 条，全部为 `terminated && cartRefilled`，当前可删项目 = 0 条** —— 该按钮对每一行都是禁用态，处于"高危 + 无用"的双输状态。
4. **权限面偏宽**：后端 `DELETE /projects/{id}` 为 `require_editor`（商务亦可删），前端仅 `canWrite` 可见，viewer 从不可用。
5. **与既有 UI 原则不一致**：资产详情页（2026-07-21 UI 规范 / ADR-024 同批）已把「删除产品」收进「更多▾」，销售项目列表却让删除常驻。

## Decision

1. **前端（销售项目列表 `sales/projects/index.vue`）**：操作列**移除常驻「删除」按钮**，改由行尾「更多▾」`el-dropdown` 承载；该下拉**仅 `isAdmin` 渲染**，普通商务（editor）与生态人员（viewer）完全看不到入口。`isUndeletable(row)` 时菜单项 `disabled` + 文案「**删除项目（撤销单不可删）**」（`el-dropdown-item` 内不支持嵌 `el-tooltip`，故用文案自解释；原常驻按钮的 tooltip 文案「撤销单保留历史，不可删除」随之退役）。操作列 `220px → 190px`。
2. **后端**：`DELETE /projects/{id}` 权限 `require_editor` → **`require_admin`**。理由：前端隐藏只是体验，**权限必须服务端收口**，否则任何 editor 持 token 直调接口仍能删。`services.delete_project` 的全部回滚逻辑与 ADR-028 §3 的 403 护栏**逐字不动**。
3. **前端（产品列表 `assets/list.vue`，本批附带）**：移除操作列「编辑」按钮。编辑入口现有 3 个（列表按钮 / 快览抽屉底部 / 详情页 `[编辑资产]`），删后仍剩 2 个，能力零损失；且该按钮对 viewer 本就是「可见但禁用 + `NO_PERM_TIP`」的噪音。操作列 `160px → 110px`。
4. **不做软删除/归档（方案 C）**：当前无「需要隐藏但保留在列表」的诉求，`terminated` 状态本身已是留痕表达；引入 `archivedAt` 需迁移且无消费方 —— 属架构过度。
5. **一次性数据清理（运维动作，非产品行为）**：清除 2 条测试遗留项目，不改变任何端点语义，详见附录。

## Consequences

- **变容易**：误删从「一次点击」变成「admin 身份 + 两次点击」，风险大幅下降；操作列释放 30px，5 按钮挤压/换行缓解；删除权限面由 2 个角色收窄到 1 个；产品列表行宽 +50px，且 viewer 视角操作列只剩「加入购物车」。
- **变难**：**商务（editor）彻底丧失项目清理能力**，误建单只能找 admin；admin 仍需逐条操作，无批量清理入口；被驳回且从未回填的死单（`terminated && !cartRefilled`）从此只能由 admin 清理，长期看列表会累积终态单（本次清理后归零，后续靠 admin 兜底）。
- **必须同步认知**：前端隐藏 ≠ 禁止删除。真正的不变量在 `services.delete_project`（ADR-028 §3 护栏 + 回滚逻辑），改前端不改后端等于零。
- **可逆性：高**。回退 = 菜单项改回常驻按钮 + 权限改回 `require_editor`，无 schema 变更、无数据迁移、无 API 结构变化。
- **数据清理部分不可逆**（唯一退路 = 备份的 db 文件）。
