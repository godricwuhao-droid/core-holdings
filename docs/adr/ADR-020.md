# ADR-020: 销售明细服务期限 + 下单入口统一收口购物车

## Status
Accepted（2026-10-20，业务已拍板：服务期限在购物车行填写；移除产品页「登记销售」直接下单入口，统一购物车下单）

## Context
现状 viewer 有两条下单链路：购物车结算 + 产品列表/详情「登记销售」直接下单（SalesOrderDialog），校验逻辑两处维护、口径易漂移。业务要求每条销售明细可填服务期限（服务开始/结束，YYYY-MM-DD，下单人填、商务审核可改）。

## Decision
1. **服务期限**：`cart_items` 与 `project_items` 各新增 `serviceStart` / `serviceEnd`（可空，YYYY-MM-DD，start ≤ end，后端校验）：
   - 购物车行填写（普通产品行与遥感明细行**均不展示**期限输入——遥感行按期数 saleMonth 售卖，期数即服务时间，不填期限）；
   - checkout 时透传落 `project_items`；重新提交（copy 预填）带出旧值可改；
   - 审核 confirm 可改（review 入参接受 serviceStart/serviceEnd）；商务手动建单页明细行同样可填（建单页 creator 也是下单人，口径一致）。
2. **下单入口统一**：前端移除「登记销售」入口（产品列表抽屉、产品详情页动作按钮）及 `SalesOrderDialog` 的非购物车模式；购物车成为**唯一**下单链路。后端 `POST /sales/order` 端点**保留并在文档标记 deprecated**（兼容潜在直调方，前端不再调用）。
3. 购物车行金额输入规则遵循 ADR-018（可输、区间校验、原价快照）。

## Consequences
- 变容易：校验/展示单一出口；服务期限随购物车行走既有数据通道（bootstrap 镜像），无需新通道。
- 变难：单笔快速下单多一步加购（业务已接受）；SalesOrderDialog 组件仅保留购物车确认模式（结算弹层），非购物车代码路径删除。
- 可逆性：高。入口删除纯前端；服务期限为可空新列。
