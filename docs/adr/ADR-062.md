# ADR-062: 购物车数量改点击即改（去 +/-）+ 审核页数量超库存截断对齐购物车

## Status
Accepted（2026-11-10，已实现 + 自测/Architect 代码核对通过：`ClickEditNumber` 加 `max`/`maxMessage`/`disabled`（commit 超 max→`draft=max`+`ElMessage.warning` **只弹一次**、**Esc 先还原 draft 再 closeEdit → 不超 max 不弹不 emit**、**不透传 `:max` 给 el-input-number** 防 EP blur 原生钳值吞警告、disabled 不可点进编辑）；① 购物车去 +/-/`stepQty`/步进器 CSS、数量格→`ClickEditNumber`(`:max=qtyMax(row)` avail 口径 + `qtyMaxMsg`)、rs 恒1/repeatSale 不限/库存副提示保留（`applyQty` 截断分支因值已≤max 不双弹）；② 审核页 `ReviewLine` 存 `assetId` + `import availableQty` + `qtyMax(l)`（rs→null、repeatSale→null、否则 `origQty+availableQty ?? 0`、asset 缺失→origQty）+ 数量格 `:max`；提示文案两页统一「可用数量仅 N，已按上限填写」；后端不动、只传变更/计算链/派生零改动；自测 F12 实锤 PUT/items 只传变更行、上限口径 origQty+avail=20 实测、Esc 还原、repeatSale 不限、rs 恒1、ADR-059/060 点击即改回归，vue-tsc 0）

## Context
两条需求：
1. **购物车数量输入**对齐审核页——去掉 `-`/`+` 步进按钮，改成"点击数值即改"（复用 `ClickEditNumber`）。
2. **审核页数量超库存**判定对齐购物车——现状是"随便填、确认时后端 400 报错"，改成"输入超上限 → 失焦/回车**截断到上限 + 黄警告**"（购物车既有行为）。

**上限口径（用户已确认）**：审核页行**已锁定库存**（购物车未锁定），故该行上限 = **`当前量 origQty + 该资产剩余可售 availableQty`**（与后端 `review` 确认 400 口径一致：`delta ≤ availableQty`）；`repeatSale` 行不限；rs 明细行恒 1 不可改。

> 本 ADR 沿用 ADR-061 的"无位数限制、库存上限为唯一约束"意图，只把购物车输入控件从 ADR-061 的步进器换成 `ClickEditNumber`。

## Decision
1. **`ClickEditNumber` 加 `max` / `maxMessage`**：commit（失焦/回车）时若 `draft > max` → 截断到 `max` + `ElMessage.warning(maxMessage)`；**Esc 还原不受影响**（还原为原值，不触发截断/提示）；`max=null/undefined` 表示不限。保持组件通用（min/max 成对）。
2. **购物车**（`frontend/src/views/cart/index.vue`）：步进器（`.cart-stepper` 的 减号+`.step-input`+加号）→ **`ClickEditNumber`**（`:model-value="row.cart.qty"`、commit 走既有 `applyQty`/`PUT /cart/{id}`、`:max="qtyMax(row)"` + 购物车式提示）；**删 `+`/`-` 按钮和 `stepQty`**（及其专属 CSS）；rs 明细行保持只读 `1`、`repeatSale` 行无 max（不限）、库存副提示（`可售 N / 已达上限`）保留。超上限**只弹一次**警告（由组件 max 负责；`applyQty` 截断分支因值已 ≤ max 不触发，别双弹）。
3. **审核页**（`frontend/src/views/sales/projects/review.vue`）：给 `ReviewLine` 存 `assetId`（展开逻辑 L135-158 已有 `it.assetId`，补存 + 接口加字段）；`import availableQty`（types.ts）；新增 `qtyMax(l)` = `repeatSale? null : Math.max(l.origQty + (availableQty(getAsset(l.assetId)) ?? 0), 1)`（asset 缺失 → max=origQty）；数量 `ClickEditNumber` 加 `:max="qtyMax(l)"` + 提示。
4. **提示文案对齐购物车**：`「{产品名}」可用数量仅 {max}{单位}，已按上限填写`。
5. **后端不动**（校验已存在、口径自洽）；**"只传变更"/`lineAmount→contractTotal` 计算链/派生/校验零改动**——截断只改 `l.qty`，"改量→金额联动"是现有行为。

## Consequences
- 易：购物车/审核页数量交互统一（都是点击即改、超上限截断+提示）；审核页超库存**实时反馈**（不再确认时才 400），与购物车体验一致。
- 难/代价：同单同资产**多行都顶到上限**时合计可能仍超 → 后端 400 兜底（提示"第 X 行"，非购物车式截断）；截断使 `l.qty` ≠ `origQty` → 进入"只传变更"提交新 qty → 金额按量联动（现有行为，可接受）。
- 可逆性：**高**（纯前端 + `ClickEditNumber` 加 max；无 schema/后端改动）。
