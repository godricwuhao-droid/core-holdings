# ADR-023: 购物车折扣率输入（选填快捷入口，金额仍权威必填）

## Status
Accepted（2026-10-21，业务要求：购物车下单处加折扣输入，选填，填后展示原价/折扣价全貌）

## Context
ADR-018 实现了"销售金额可输 + 区间校验 + 原价快照"，但界面上没有显性的"折扣"概念（列名叫销售金额），生态人员找不到折扣入口（2026-10-21 用户反馈）。需要一个选填的折扣率快捷入口，且填后能看到原价单价/原价总额/折扣单价/折扣总价全貌；商务审核时能看到折扣率、折扣价与原价。

## Decision
1. **新字段 `discountRate`**（number 0-1 小数，如 0.9=九折；可空）：
   - `cart_items.discountRate`（购物车行，选填）；
   - `project_items.discountRate`（下单时快照，只写不改，与 origPrice 同级口径）。
2. **交互**：购物车金额列内联一个小型「折扣」输入（单位：折，0-10 一位小数，如 9 / 8.5）。输入折扣 → 自动计算 `销售金额 = round(原价单价 × 数量 × rate)`（整数元，ROUND_HALF_UP）回填金额输入框；**手动编辑销售金额 → 清空该行 discountRate**（金额是权威值，折扣率只是快捷工具，防止"显示9折但金额已被手改"的不一致）。
3. **展示（不破坏 40+18 统一行结构）**：原价单价=单价列（已有）；原价总额与折扣单价=金额列提示行小字（11px，如 `原价总额 ¥X · 折后单价 ¥Z`，超长省略+tooltip）；折扣总价=销售金额输入框值+小计列（已有）。
4. **校验**：折扣回填的金额走现有全部校验（整数元>0、参考区间 ADR-018/021）；折扣率本身 0<rate≤10（折）。
5. **审核页**：明细行新增「折扣」展示列（discountRate → "九折"，null 不显示），与已有原单价/原金额 + 可编辑终审价并列——商务可见"原价、折扣率、折扣价"三要素，终审改价能力不变。

## Consequences
- 变容易：生态人员折扣操作路径显性（填 9 → 金额自动算好）；商务审核信息完整（折扣率留痕）。
- 变难：多一张表两列 + 一致性规则（手改金额清 rate）多一条前端逻辑；"折扣率"与"手动金额"双路径需长期维护说明（已写入契约）。
- 可逆性：高。两可空列 + UI，revert 即回退。
