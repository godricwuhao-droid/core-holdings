# ADR-037: 生态人员（viewer）购物车口径：折扣下线 + 参考价区间上限放开

## Status
Accepted（2026-10-22，业务需求：生态人员下单简化）

## Context
1. 生态人员（viewer）在购物车里同时面对「销售金额（必填权威）」与「折扣（选填快捷）」两个入口，实际业务中生态人员按合同谈定金额直接填，折扣率只是冗余快捷方式，且历史上是金额口径混乱的源头之一（BUG-06 同源）。
2. 参考价区间（`priceMin/priceMax`）当前对**所有角色**双向校验：生态人员谈价高于参考价上限（加价成交）时会被 400 挡住，业务上应允许"不低于成本下限、上不封顶"。

## Decision
1. **折扣入口对 viewer 下线**：购物车折扣输入（列）对 viewer **不渲染**；商务/管理员（editor/admin）保持现状（ADR-023 不动）。
2. **后端宽松**：viewer 的购物车行若带历史 `discountRate`（本 ADR 之前录入），结算/改价时**忽略**该值（不 400，金额仍为权威）——否则存量行会被永久卡死且前端已无清除入口。OpLog 不额外留痕（金额行本身就是权威口径）。
3. **区间校验分角色**：viewer 提交/修改行金额时，仅校验 **下限**（`amount < priceMin → 400`）；**上限放开**（`amount > priceMax` 允许）。editor/admin 维持双向校验。遥感明细行（ADR-021 明细级区间）同口径分角色。
4. 结算（checkout）链路沿用行上已持久化的 `amount/discountRate`，不新增入参；校验点统一在 `PUT /cart/{id}`（改价/改量）与 checkout 权威链各执行一次（同函数，角色取自当前登录用户）。

## Consequences
- **变容易**：生态人员购物车少一列输入、少一类 400；加价成交不再被挡。
- **变难**：区间校验函数需要角色参数（`max_allowed: float | None`），调用方多传一个值；viewer 折扣被静默忽略，若将来想"恢复 viewer 折扣"需查存量数据。
- **可逆性**：高。回退 = 恢复渲染条件与校验分支；无 schema 变更、无数据迁移。
