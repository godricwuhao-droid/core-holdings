# ADR-016: 购物车结算分组键改为 (assetId, customer)，一资产一客户一记录

## Status
Accepted（2026-10-20）

## Context
BUG-20261020-#3：`checkout` 按 `assetId` 单键分组生成合同（ADR-013 的"一资产一记录"），同一产品多客户行被静默合并为一条记录，`customer` 取第一行；而前端结算预览按客户分组提示"将生成 N 份销售记录"。两边口径不一致，客户归属、对账、提成统计错乱。加购/改客户链路（`patch_cart_item`/`add_to_cart_batch`）本身允许同产品不同客户并存。

## Decision
1. `checkout` 分组键改为 `(assetId, customer)`，每组合并数量/金额后生成一条 `ContractInput`；合同 `customer` 即分组键客户。
2. 前端 `previewGroups` 预览口径同步改为 `(assetId, customer)` 双键分组，保证"N 份销售记录"提示与落库一致。
3. ADR-013 的口径描述由"一资产一记录"修订为"一资产一客户一记录"（在 ADR-013 中追加 Superseded 注记，指向本 ADR）。
4. 不改变手动建单链路（`_create_project_core`）行为。

## Consequences
- 变容易：预览与落库口径一致；客户归属与金额不再串账；前端只需改分组键。
- 变难：同一产品卖给多个客户会生成多条销售记录（合同数变多），审核列表更长；与 ADR-013 原文描述产生出入（需同步文档）。
- 可逆性：高。分组键是纯逻辑改动，无 schema 变更；回滚即恢复单键分组。
