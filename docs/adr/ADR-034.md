# ADR-034: 登录加固与凭据吊销

## Status
Accepted（2026-10-22，来源：`business-logic-bugs-20261022.md` BUG-11 / BUG-12）

## Context
1. `JWT_SECRET = os.getenv("JWT_SECRET", "<源码内默认值>")`：未设环境变量时，拿到源码即可离线签发 `{"sub":"1"}`（admin 为 `users.id=1`）接管全站。
2. token payload 无 `jti`/版本号，改密后旧 token 仍有效 7 天；无登出端点（前端仅清 localStorage）。
3. 登录失败文案区分「账号已被禁用」与「用户名或密码错误」；`user is None` 时短路不做 PBKDF2（时间差可枚举账号）；失败计数只有 username 维度 → 换用户名喷洒可绕过，且 10 次错误可定向锁死管理员 15 分钟；`_login_fails` 为进程内无界 dict。

## Decision
1. **fail-fast**：`JWT_SECRET` 缺失或等于内置开发值时，生产启动（`APP_ENV != "dev"`）直接抛错退出。开发环境密钥优先级：环境变量 > **`backend/.jwt_secret` 持久化文件**（0600，已 git 忽略；不存在则原子生成）> 目录只读时退回进程内随机密钥（打印 ⚠️）。
   > 实施修正（FIX-20261022-FOLLOWUP）：原设计"dev 进程内随机密钥"会导致 `--reload` 每次热重载全部 token 失效，改为文件持久化；首次落盘时旧 token 失效一次，之后重启不再失效。
2. **tokenVersion 吊销**：`users.tokenVersion`（默认 0）写入 JWT；`get_current_user` 每请求比对，不一致 → 401。**改密 / 禁用 / 角色变更**时 `tokenVersion += 1`。
3. **不做 `/auth/logout` 服务端端点**：登出仍为前端清 token。理由：单 token 无 refresh 机制，bump 版本会让所有设备同时下线，与"登出"语义不符；吊销靠改密即可。此取舍记录在案，若后续引入 refresh token 再补。
4. **登录加固**：
   - 统一失败文案「用户名或密码错误」；用户不存在时仍执行一次 PBKDF2（恒定时间）；
   - 失败计数改为 `(ip, username)` 维度 + 纯 IP 维度（阈值 10/15min 与 30/15min），超限返回 **429**「登录尝试过于频繁，请稍后再试」；
   - 不再因单账号计数全局封禁；`_login_fails` 改为有界结构（最多 10k 键，LRU 淘汰）。
5. **`/users/options` 提权为 `require_editor`**（见 ADR-030）。

## Consequences
- **变容易**：密钥缺失不会静默上线；改密/禁用可即时吊销；枚举与喷洒成本显著提高。
- **变难**：本地开发如果依赖"固定 token 长期有效"会受影响（随机密钥重启失效，需重新登录）——开发体验的代价，换取默认安全。
- **可逆性**：**高**。全部为增量列 + 校验；回退只需移除版本比对（但不建议）。
