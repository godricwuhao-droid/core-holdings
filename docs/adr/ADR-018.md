# ADR-018: 价格体系重构——参考区间 + 折扣价（原价快照）+ 关闭挂牌价回写

## Status
Accepted（2026-10-20，业务已拍板：按单价校验、未设区间不限制、关闭并删除审核改价回写挂牌价功能）

## Context
现状：Asset 仅有 `salePrice` 单值；viewer 下单 unit 模式金额不可输（后端按 salePrice×qty 权威重算）；`ProjectItem.price/amount` 被审核改价直接覆盖，**原价无法保留**；审核 confirm 会把终审价回写 `assets.salePrice`，引入折扣后挂牌价会被每笔折扣单污染。

## Decision
1. **参考区间**：`assets` 新增 `priceMin` / `priceMax`（可空，元/份，商务/管理员在产品页维护，选填）。校验口径：行折扣单价（amount ÷ qty）须在 `[priceMin, priceMax]` 内；**产品未设置区间 = 不限制**（min/max 只填其一则只校验该边界）。
2. **原价快照**：`project_items` 新增 `origPrice` / `origAmount`，下单时快照写入、**永不覆盖**（unit 行：salePrice / salePrice×qty；amount 行：salePrice / salePrice×qty；遥感行：rs_items.price / 同值）。`price/amount` 语义 = **最终价（折扣/终审后）**。合同总额 = Σ 最终行金额；`soldAmount` 累计最终金额。
3. **生态下单可输金额**：viewer 购物车行金额可输（整数元，unit 行放开），选填——不输 = 原价成交（salePrice×qty）；超区间 400。
4. **删除挂牌价回写**：`review_project` confirm 中回写 `assets.salePrice` 的逻辑整体删除；挂牌价与区间仅由产品管理维护。审核终审改价只写 `ProjectItem.price/amount`（orig 不动）。
5. 遥感明细行金额：允许下单输折扣金额（同样受区间/原价快照规则约束；遥感行未设区间即不限制）。

## Consequences
- 变容易：原价/折扣价全链路可展示可对账；挂牌价与订单价格解耦；审核页"终审"语义清晰（只定本单价格）。
- 变难：金额权威来源从"后端单价重算"转为"用户输入 + 区间校验"，后端必须在每个入口（购物车行更新、checkout）做校验，不能信任前端；存量订单 origPrice/origAmount 为空（展示端按 price/amount 兜底显示）。
- 可逆性：高。均为可空新列 + 逻辑分支；回写删除属行为变更，revert 代码即恢复。
