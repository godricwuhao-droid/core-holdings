# ADR-025: 卫星 Token 数量单位「个」+ 单价展示百万Token 口径

## Status
Accepted（2026-10-21，业务要求：Token 单价为无限循环小数 0.033333… 元/个（=33,333.33 元/百万Token），需要与对外报价一致的展示口径）

## Context
卫星 Token（pricingMode='amount'）实际定价 33,333.33 元/百万Token，按「1 个 = 1 Token」计数量时单价是无限循环小数。若展示「元/个」两位小数（0.03）会失真约 10%（折算 30,000/百万Token），6 位小数违背金额两位小数规范。且旧单位文案「颗（Token 额度）」与实际计量（1 个 = 1 Token）不符。展示必须与客户报价语言（百万Token）对齐。

## Decision
1. **数量单位**：卫星Token 计量单位 = 「个」（1 个 = 1 Token）：
   - 前端 `constants.ts` CATEGORY_UNITS 卫星Token 行 unit 改为 `个`；
   - 存量 3 个卫星 Token 产品（CH-SAT-001/002/003）DB 内 `unit` 同步改；
   - 数量展示继续走 `formatTokens`（如 3 亿 / 13700 万），不变。
2. **单价展示口径（仅展示层）**：amount 模式产品的销售单价展示统一换算到百万Token 口径：`round(salePrice × 1,000,000, 2)` 显示 `¥33,333.33/百万Token`（formatMoney 两位小数 + 千分位）；覆盖位置：产品列表、产品抽屉、产品详情的销售单价行（amount 模式统一走此口径，unit 模式展示不变）。后端无展示逻辑改动。
3. **数据**：3 个卫星 Token 产品 `salePrice` 写入 `0.03333333`（元/个，8 位小数；×1e6 展示 = 33,333.33）。salePrice 在 amount 模式下本就是派生/展示值（ADR-008），写入不影响交易。
4. **交易链路零改动**：amount 模式合同金额（整数元）权威输入、下单/审核/折扣校验（Token 产品区间维持空=不限制）全部不变。

## Consequences
- 变容易：客户看到的价格与实际报价语言（百万Token）一致，可直接对账；循环小数问题被「展示换算」消化，存储值仅作派生。
- 变难：amount 模式单价展示多一条换算分支（前端）；若未来 Token 定价不再是 3.33 万/百万Token 的循环小数场景，展示逻辑依然通用（×1e6 两位小数）。
- 可逆性：**高**。纯展示换算 + 单位文案 + 3 行数据，revert 即回退（数据有脚本备份）。
