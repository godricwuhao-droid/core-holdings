# ADR-028: 生态人员订单提交后禁止编辑（唯一改单路径 = 撤销 → 购物车重下）

## Status
Accepted（2026-10-21，业务要求：生态人员提交销售项目后不允许再编辑，只能撤销后回购物车重新下单，且撤销记录必须保留不得删除）

## Context
2026-10-16 曾开放「生态人员（viewer）可编辑自己下单项目的基本信息」（`services.update_project` 内 viewer 分支 + 前端列表/详情/编辑页三处入口）。业务现在要求收回该权限：**订单一旦提交即冻结**，改单只能走「撤销 → 明细回填购物车 → 改单重新结算」。

关键现状（决定了本 ADR 只需补「编辑权」这一块）：
- 系统**没有草稿态**：viewer 下单 → `POST /projects` 直接生成 `pending`。「提交后禁编辑」在状态机上等价于「viewer 禁止编辑」——不需要按状态做条件判断。
- 撤销链路已完备：`POST /projects/{id}/withdraw`（ADR-026）仅 `pending` 可调，语义 = 终止原单（释放真实锁定 + `cancel_release` 流水 + 合同 remark 追加「撤销：{原因}」+ OpLog「撤销订单」+ 审计）**+ 明细回填下单人购物车**，原单保留 `terminated` 不物理删除。
- 重新下单入口已完备：`POST /projects/{id}/refill-cart`（ADR-027，幂等标记 `Project.cartRefilled`）→ 前端跳 `/cart` 改单结算。
- 留痕展示已具备：详情页「销售记录」卡片渲染合同 `remark`（含「撤销：原因」），操作日志页签展示 OpLog。

## Decision

1. **收回 viewer 的编辑权（服务层一处收口，不看状态）**
   `services.update_project` 对 `user.role == "viewer"` 一律 `403 "订单已提交，不可编辑；如需修改请「撤销」后重新下单"`。
   删掉原「viewer 可编辑自己 pending 项目」分支与 `rep` 字段的 viewer 特判（该特判为编辑权的子约束，父权限消失后即为死代码）。
   **商务/管理员规则不变**：pending 仅商务负责人或 admin 可编辑基本信息；存在 `delivered` 合同或派生 `terminated` 不可编辑。

2. **前端入口收敛（四处，全部按 `isViewer` 硬关）**
   - `sales/projects/index.vue` `canEditProject`：`isViewer` → `false`；行操作 tooltip 文案改为「订单已提交，不可编辑，如需修改请「撤销」后重新下单」；`编辑` 列对 viewer 不再渲染（连禁用态也不给，避免误导）。
   - `sales/projects/detail.vue`：viewer 隐藏头部「编辑」按钮（保留「撤销」与「重新提交」）；`goEdit` 对 viewer 直接拦截兜底。
   - `sales/projects/create.vue`：非 admin 的 viewer 访问 `/sales/projects/:id/edit` → 提示后 `replace` 到详情页（页面保留，供商务/管理员使用）。
   - `router/index.ts` `viewerAllowedPath`：从 `/^\/sales\/projects\/\d+\/(detail|edit)$/` 中**去掉 edit**，仅放行 detail。

3. **撤销记录不可删除（硬删除护栏）**
   `DELETE /projects/{id}`（`require_editor`）新增守卫：`p.status == "terminated" and p.cartRefilled` → `403 "该订单已撤销（或已回填购物车）并将保留历史记录，不可删除"`。
   实现选择：**复用 `cartRefilled` 标记**，不新增列、不做迁移——语义由「购物车已回填」扩为「该终止单已产生回填/撤销留痕」，恰好覆盖「已撤销单不得删除」。
   其他终态项目（被驳回且从未回填）仍允许商务清理；管理员确需清理撤销单走数据库运维，不做接口后门。

4. **保留 viewer 对「已审批项目」的终止权（不随编辑权一起收回）**
   `change_project_status` 现有约束不变：viewer 仅可对**自己下单**项目置 `terminated`（需填原因），不可交付。
   理由：撤销只对 `pending` 生效；若同时剥夺终止权，`active`（已审批）项目对生态人员将没有任何退出路径，只能找商务人工处理，运营成本更高。
   **语义边界（需在文档与 UI 文案中保持区分）**：撤销 = 待审核单撤回**并回购物车**；终止 = 已生效单作废**不回购物车**。

5. **留痕可见性补一条（轻量）**
   详情页在 `status === "terminated" && cartRefilled`（撤销导致）时，头部下方展示一行浅色提示：「该订单已撤销，历史记录已保留；撤销原因见销售记录备注」+ 右侧「重新提交」入口复用既有按钮。不新增后端字段（判据用既有 `cartRefilled`）。

## Consequences
- **变容易**：viewer 权限模型退化为「只读 + 撤销/终止/重新提交」，无状态分支，越权面显著收窄；改单动线唯一（购物车），与 ADR-026/027 的既有动线闭环；撤销留痕有硬护栏，不会被商务误删。
- **变难**：生态人员改一个备注也要整单撤销重下，操作成本上升（业务已确认接受）；`create.vue` 中 viewer 编辑相关分支成为不可达代码，需后续清理；`DELETE /projects` 少了一条清理路径，脏数据只能运维处理。
- **口径风险**：`cartRefilled` 兼作「撤销留痕」标记后，被驳回单在用户点过「重新提交」后也会变成不可删除——属预期内的「终止即留档」，但与字段名语义有偏差，已在 Decision 3 显式记录。
- **可逆性**：**高**。后端为两处判空 + 一个 `if`；前端为四处显隐/路由正则；无 schema 变更、无数据迁移，回退只需恢复 viewer 分支与路由放行。
