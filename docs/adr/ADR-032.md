# ADR-032: 状态机守卫下沉 + 终止按明细状态回滚 + 派生补全

## Status
Accepted（2026-10-22，来源：`business-logic-bugs-20261022.md` BUG-03 / BUG-04 / BUG-17 / BUG-14）

## Context
合同/项目状态机有三处结构性缺陷：

1. **守卫写错层**：ADR-019「先录签订时间 → delivering → 可交付」的守卫在 `change_contract_status`（`services.py:1326`），而项目级批量交付直接调 `_change_contract_status_core`（`1720-1726`）→ **绕过守卫**。
2. **回滚按合同状态二选一**：终止分支 `if from_status in ("active","pending","delivering") → 释放锁定 else → 撤销全部交付`（`1771-1789`）。但"撤销部分交付"会把合同置回 `delivering`（`2045-2057`），此时终止只释放剩余锁定，**已交付明细的 `shippedQty`/`soldAmount`/交付单永久残留**，且项目删除也不会再回滚。
3. **派生表漏组合**：`_derive_project_status`（`1265-1270`）对 `{delivered, terminated}` → `active`（显示"进行中"），且项目级接口 `targets` 为空 → 永久 400，单据无出口。

## Decision
1. **所有交付前置条件下沉到 `_change_contract_status_core`**：`status == "delivered"` 必须满足 `from_status == "delivering"` 且 `signedDate` 非空、无 `pending_asset` 明细；合同级与项目级批量共用。
2. **项目级批量改为"全量或全不"**：先收集所有不合规合同 → 一次性 400 列出（编号 + 原因），不做部分执行。
3. **终止按明细实际状态回滚**（不再按合同状态分支）：
   - `it.status == "shipped"` → 撤销该明细对应交付（回退 `shippedQty`/`soldCount`/`soldAmount`，交付单置 `reverted`）；
   - `it.status ∈ {locked, confirmed}` → 释放锁定；
   - 无产品（`asset` 已删）/无明细 → **400**（不允许"静默成功、零回滚"）。
4. **`delete_asset` 守卫扩展**：存在 `delivered` 合同引用 → 400「该产品存在已交付销售记录，不可删除」。
5. **派生规则补全**：`statuses ⊆ {delivered, terminated}` 且含 `delivered` → `delivered`（已完成，剩余作废）；`{pending, terminated}` → `terminated`；其余不变。

## Consequences
- **变容易**：状态机只有一处变更入口，规则可枚举测试；作废单据不再留下销量残留。
- **变难**：项目级批量从"能交付几条就交付几条"变为"一条不合规全批失败"，商务需先补齐签订时间（属预期收紧）；`delete_asset` 收紧后历史产品只能通过"先终止合同"再删。
- **可逆性**：**中**。代码可回退，但**回滚口径变化会影响存量交付数据**（旧行为下已产生的残留无法自动识别），修复时需输出一份"疑似残留合同"只读清单供人工确认。
