# ADR-047: 购物车服务期限由必填改为选填（半填仍拦截）

## Status
Accepted（2026-10-26，业务拍板：服务期限改为可选，只放开「两端都空」）

部分取代 [ADR-022](ADR-022.md) §1 第三条——ADR-022 中「客户非空」「销售金额 > 0 整数元」两条必填口径**保持不变**。

## Context
ADR-020 引入服务期限（`serviceStart` / `serviceEnd`）时口径为选填，ADR-022（2026-10-24）出于「结算信息完整」的考虑把普通产品行的服务期限升级为起止均必填。

实际使用中部分订单在结算时点尚未确定服务起止（框架协议、待开通、期数另行约定等），强制填两个日期导致下单人只能填占位日期（如当天 ~ 当天），反而污染了后续商务审核与交付环节的真实服务期数据。

## Decision
1. **普通产品行服务期限改为选填**，三态口径：
   - 两端都空 → **合法**，`serviceStart` / `serviceEnd` 落库为 `NULL`；
   - 只填一端 → **仍拦截**（成对校验），后端 400 计入缺项、前端两端输入框同时标红；
   - 两端都填 → 保持 ADR-020 校验不变（`YYYY-MM-DD` 格式 + `start ≤ end`）。
2. **校验时点不变**（沿用 ADR-022 §2）：行更新（`POST/PUT/PATCH /cart`）始终允许暂存任意状态；仅 `POST /cart/checkout` 强制成对。
3. **遥感明细行（`itemId` 非空）继续豁免**（ADR-020：期数即服务时间），行为不变。
4. **客户、销售金额必填口径不变**（ADR-022 §1 前两条继续有效）。
5. 前端视觉口径同步：服务期限列头去掉必填红星（`*`），tooltip 改「选填（开始/结束日期需成对填写…）」，placeholder 加「（选填）」。

### 为什么只放开「两端都空」，不允许单边
- 下游展示（`sales/projects/detail.vue`）按 `start ~ end` 拼接，单边会渲染成 `2026-11-01 ~ -`；
- 商务审核页（`review.vue`）按「原值 vs 新值」判断是否提交变更，单边空值语义模糊（是「未定」还是「清空结束日」）；
- 单边期限在业务上没有解释空间（服务期天然是区间），允许单边只会把问题推到下游。

## Consequences
- 变容易：未确定服务期的订单可以直接结算，不再需要填占位日期；落库 `NULL` 语义清晰（= 未约定服务期）。
- 变难：商务审核与交付环节需要自行补齐服务期（原本下单时必填）；统计「有服务期的订单占比」时需排除 `NULL`。
- 可逆性：**高**。仅一处校验分支 + 前端呈现，revert 即恢复必填；DB 列本就是 `nullable=True`，无迁移。
- 存量数据：历史行有值/空值均不受影响，无需回填。

## 变更范围
- 后端逻辑：`backend/src/services.py`（`checkout` 逐行必填校验分支）
- 后端注释：`backend/src/services.py`（`checkout` docstring / 校验注释）、`backend/src/routers/api.py`（`POST /cart/checkout` docstring）
- 前端：`frontend/src/views/cart/index.vue`（`serviceMissing()` 标红口径、`openOrder()` 结算前置校验、列头红星与 tooltip、两个 date-picker placeholder、顶部提示条文案）
- 未改动（已支持空值）：`models.py`（两处列 `nullable=True`）、`_validate_service_period()`、行更新接口、`sales/projects/create.vue`（手动建单本就选填）、`review.vue`、`detail.vue`
- 记录：`docs/api-contracts.md`、`docs/backend/api.md`、`docs/backend/changelog.md`、`docs/frontend/changelog.md`、`docs/architecture.md`

## 验证（副本库实测，不触碰生产库）
复制 `core_holdings.db` 到 `/tmp` 并以 `DATABASE_URL` 指向副本另起 8001 实例，admin 登录后逐例验证（产品 #2 智元机器人-X2，qty 1，金额 1305000）：

| 用例 | 期望 | 实际 |
|---|---|---|
| 两端都不填 | 200 建单 | ✅ 200，`project_items.serviceStart/serviceEnd` 均 `NULL` |
| 只填开始日期 | 400 | ✅ `购物车存在必填缺项，请补齐后再结算：智元机器人-X2：服务期限（开始/结束日期需成对填写，或都留空）` |
| 只填结束日期 | 400 | ✅ 同上（对称） |
| 两端都填且顺序正确 | 200 建单 | ✅ 200，落库 `2026-11-01` / `2026-12-31` |

另：`python3 -m compileall -q src main.py` 通过；前端 `read_lints` 无新增诊断。
