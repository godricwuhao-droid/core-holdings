# ADR-055: 销售项目列表页服务端分页（`/sales/projects`）

## Status
Accepted（2026-11-04，已实现 + QA 独立回归全绿：`GET /projects` 服务端分页（page/pageSize + 可见性 build_visibility + keyword/status/rep/businessOwner 过滤 + {total,items}、排序 id.desc、keyword 用 SQLite instr 大小写敏感精确对齐前端 JS includes）；列表页改分页请求驱动 + el-pagination + 卡头显后端 total + 写操作后重载；bootstrap 全量 projects 不动（13 消费点零回归）；QA 3 角色×7 条件对齐校验 code 有序集合逐条相等、可见性 viewer/editor/admin/finance 正确、大小写敏感、参数 422/401，无新缺陷）

## Context
用户要求 `/sales/projects`（销售项目列表页）加分页，且明确**后端分页**（区别于 ADR-054 账号页的客户端分页）。

现状（code-explorer 摸底）：
- 页面 `views/sales/projects/index.vue`（router L55-59，无 meta）。角色：**viewer** 可看（仅自己下单，后端过滤）、**finance 禁入**（守卫只放 /assets）、admin/editor/supervisor 全量。
- 数据 = **bootstrap `db.projects`（全量可见项目）+ 前端 computed 本地过滤**（`list` L181-192），**无独立 fetch、无 `el-pagination`**。
- 表格 11 列（L452-638）；**4 个前端本地过滤**：`searchText`（匹配 name+code+customer，L184）、`statusFilter`（L185）、`repFilter`（L186，选项由 db.projects 收集 L175-179）、`ownerFilter`（含 `__none__`，L188-189）；卡头「共 N 条」（L424 = 本地过滤后条数）。
- **后端无 `GET /projects`**（项目只走 bootstrap，api.py 51 路由确认）。可见性 `user_sees_project`（services.py L132-152）+ `build_visibility` 预计算 `project_ids`（L287-294）；bootstrap 在 **Python 层**过滤（L4311-4313）；排序 `id.desc()`（L4305）。
- **`db.projects` 共 13 个消费点**：列表页（L176/L182）、detail（L144）、create（L277/L560）、review（L51/L389）、outbound 下拉（L107/L132/L166）、资产详情销售关联（L100/L930-935）、api 层 `projectItemsOfAsset`（L390）+ `getDashboard` 看板统计（L429-452，dashboard 间接消费）→ **bootstrap 不能改分页**。
- 现成服务端分页范式：`GET /audit-logs`（api.py **L231-248**：page/pageSize + count + offset/limit + `{total,items}`）+ 前端 `listAuditLogs`（api/index.ts L1122-1142）+ users.vue 审计 tab（reactive 状态 + loadAudit + 换页 refetch + el-pagination L474-482）。

## Decision
| 项 | 决定 |
|---|---|
| **端点方案** | **新增 `GET /api/projects`（服务端分页，仅列表页用）**；**bootstrap 的全量 `projects` 保持不动**（13 消费点零影响） |
| **过滤** | **真后端分页**：现有 4 个过滤（keyword/status/rep/businessOwner）**全部做成 query 参数**，服务端 filter+count+切片（页内条数一致）；**服务端过滤逻辑与现有前端 `list` computed（index.vue L181-192）逐条对齐**，保证分页前后可见集合一致 |
| **可见性** | 复用 `build_visibility`/`user_sees_project` **同一口径**：restricted 角色 `where Project.id.in_(vis.project_ids)`，admin/supervisor 不限定 |
| **total 口径** | 「可见 ∩ 满足全部过滤条件」的 count（filter 之后 `q.count()`） |
| **排序** | `Project.id.desc()`（与 bootstrap/audit 一致；`createdAt` 无索引字符串不用于排序） |
| **分页参数** | `page`（ge=1, 默认 1）、`pageSize`（ge=1, le=100, **默认 20**，与 audit 一致；前端可选 10/20/50/100） |
| **卡头 total** | 「共 N 条」（L424）改显**后端 `total`**（audit tab L433 先例） |
| **过滤下拉选项** | rep/owner 下拉**选项**仍来自 `db.projects`（bootstrap 全量可见集，选项=全部可见 rep/owner，正确）；**表格数据**用新分页接口 |
| **写操作后** | 列表页写操作（分配/接手/审核/删除/撤销/改派等）后 **`loadProjects()` 重载当前页 + `refresh()` 刷新 db 镜像（供下拉选项）** |

### 接口契约
**`GET /api/projects`**
- 鉴权：`get_current_user`（viewer/editor/supervisor/admin；finance 进不了页面，按可见性自然空集）。
- Query：`page`(ge=1, 默认 1)、`pageSize`(ge=1, le=100, 默认 20)、`keyword?`、`status?`、`rep?`、`businessOwner?`。
- 逻辑：可见性（`vis.project_ids`，restricted 才 `id.in_`）→ 应用过滤：
  - `keyword`：`name LIKE %kw% OR code LIKE %kw% OR customer LIKE %kw%`
  - `status`：**与现有前端 `statusFilter` 同字段同取值**（若前端过滤的是存 `p.status` 则 `Project.status ==`；若过滤的是派生 `projectOutcome`，回报 Architect 再定口径）
  - `rep`：`Project.rep == rep`
  - `businessOwner`：`__none__` → 空/None，否则 `Project.businessOwner == businessOwner`
  → `total = q.count()` → `order_by(Project.id.desc()).offset((page-1)*pageSize).limit(pageSize).all()` → 返回 `{"total": total, "items": [ProjectOut...]}`。
- **过滤条件逐条对齐 index.vue L181-192**（backend-dev 先读该段再实现）。

### 前端改动
1. `views/sales/projects/index.vue`：
   - reactive 分页状态 `{page, pageSize:20, total, items, keyword, status, rep, owner}`（仿 audit tab users.vue L237-245）。
   - `loadProjects()` → `listProjects(...)` → 写 `items`/`total`。
   - 表格 `:data` 从本地 `list` computed 改分页 `items`；**移除**原 L181-192 的 db.projects 本地过滤（改服务端）。
   - **保留** rep/owner 过滤**下拉选项**收集（仍从 `db.projects` 全量可见集，L175-179 等）。
   - 过滤变更 → `page=1` + `loadProjects()`；切页/切条数 → `loadProjects()`。
   - `el-pagination`（仿 audit L474-482，`layout="total, prev, pager, next, sizes"`）插在 `</el-table>`（L638）后、`</el-card>`（L639）前。
   - 卡头「共 N 条」（L424）→ 后端 `total`。
   - 写操作后 → `loadProjects()` + `refresh()`。
2. `api/index.ts`：加 `listProjects(query)`（仿 `listAuditLogs` L1130-1142）返回 `{total, items: Project[]}`；**bootstrap 链路（L178-199/L183）不动**。

## Consequences
**变容易**：项目列表服务端分页（可扩展、页内条数一致）；过滤与分页一体化。

**变难 / 风险**：
- **服务端过滤必须与现有前端逻辑逐条对齐**（尤其 status 是存 `status` 还是派生 `projectOutcome`、keyword 匹配字段、owner 的 `__none__`）——否则分页后结果集与之前不一致（**QA 重点核对：分页前后可见集合一致**）。
- rep/owner 下拉选项仍依赖 bootstrap 全量（bootstrap 保留，无影响）。
- viewer 仅自己单（可见性同口径）、finance 禁入（守卫不变）。
- 列表页写操作后需同时重载表格（分页接口）+ 刷新 db 镜像（供选项）。

**可逆性**：高——新增 1 端点 + 前端列表页改造；bootstrap 与 13 消费点不动。

## 任务拆分
- **backend-dev**：新增 `GET /projects`（分页 + 可见性 + 4 过滤 + count + 切片 + `{total,items}`，排序 `id.desc`；**过滤逻辑先读 index.vue L181-192 逐条对齐**）。自测：翻页/切条数、各过滤+组合、total=可见∩过滤、viewer 仅自己单、finance 空、**与分页前 db.projects 本地过滤结果一致**。
- **frontend-dev**：列表页改分页请求驱动 + el-pagination + 卡头 total + 写操作重载 + api `listProjects`（bootstrap 不动）。`vue-tsc` 0。
- **QA**：分页/过滤/组合/total + 护栏（可见性跨角色 viewer/editor/supervisor/admin、finance 禁入、写操作后重载、rep/owner 下拉选项完整、**看板/outbound 下拉/资产详情/项目详情等 bootstrap 消费点零回归**）。
