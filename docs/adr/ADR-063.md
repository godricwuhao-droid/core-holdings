# ADR-063: 购物车——库存行内提示回移数量列（修错位）+ 删除顶部 .cart-notice 说明条

## Status
Accepted（2026-11-10，已实现 + 自测/Architect 代码核对通过：① `已达上限/可售` 库存提示从销售金额列(754-759)回移**数量列** `.cell-hint`(700-705) `v-else-if="typeof availOf(row)==='number'"` 分支（带 null 保护防 "可售 null"）、`cart-sellable-max` 着色保留(1027)、保持列内居中(与数量值同轴)，金额列(749)只留参考区间提示；分支序 rsItem→固定1 / isAmount→Token / repeatSale→不限 / 库存提示；② 删 `.cart-notice` 模板(586-595)+CSS(982-1005)+`InfoFilled` import + 陈旧注释(658/730-731/ADR-052 列注释)。**isAmount(Token)行决策**：`availOf` 对 amount 行返回 number(后端 `set_cart_qty` 同样按 `_avail` 卡同产品合计)，但 Token 行**只显 `X Token` 不叠库存提示**(isAmount 分支在前)——Token 按金额购买、主要约束是参考区间+必填、库存上限极少触发(后端400+参考区间兜底)、148px 窄列叠两条会挤；如需 Token 行也显示库存提示=小跟进。纯前端展示层，未动 availOf/qtyMax/applyQty/ClickEditNumber/参考区间/必填校验/计算链/列宽，vue-tsc 0；自测含普通产品对齐前后对比、repeatSale/rs/Token 三类、金额列只剩区间提示、notice 已删无塌陷、必填标红、ADR-061/062 回归）

## Context
用户报购物车页（`frontend/src/views/cart/index.vue`）两处 UI 问题：
1. **行内提示错位**：数量列下方的库存提示（`已达上限 {x}` / `可售 {x}`）相对上方**数量值**明显偏右、没对齐。
   - 根因（code-explorer 确认）：该库存提示**不在数量列**，而在**销售金额列**的副提示区（`cart/index.vue:754-759`）——是 **ADR-052 删除「销售单价」列时把「可售/已达上限」库存提示迁到销售金额列**的遗留。数值在数量列（148px）、提示在金额列（200px），两列各自内部都居中，故提示相对数值整体右移约一列（~174px）→ 视觉"错位"。
2. **顶部说明条冗余**：页面顶部 `.cart-notice`（ⓘ + "下单前请完善关键信息…"整段：必填口径 / 参考区间双向约束 / 数量约束 / 下单分组流程）现已被**列内行内提示 + 列头 tooltip** 覆盖，用户要求删除。

## Decision
1. **库存提示回移数量列（修错位）**：把 `cart/index.vue:754-759` 的「已达上限/可售」提示移入**数量列** `.cell-hint`（702-706）作 `v-else` 分支（前序分支已排除 `rsItem`/`isAmount`/`repeatSale`），**保持列内居中**（两列均 `align=center`，回移后与数量值天然同轴居中）；`cart-sellable-max` 着色逻辑原样保留。销售金额列 `.cell-hint`（742-760）只保留**参考区间**提示（750-752）。
   - **isAmount（Token）行**：数量列显 `X Token`；需核此类产品是否真有 per-unit 库存上限（`availOf` 是否非 null）——**若本质不限则只留 `X Token`（推荐）**；若有真实库存上限再定如何与 Token 共存。由 frontend-dev 核实并回报（不阻塞正常产品对齐主目标）。
2. **删除 `.cart-notice`**：删模板（586-595）、CSS（982-1005）、`InfoFilled` import（14 行）；顺手清理引用"顶部提示条"的陈旧注释（658、730-731 行）。

## Consequences
- 易：库存提示与数量值同轴对齐（直观、语义正确）；金额列更清爽；删说明条后表格上移、布局无塌陷。
- 难/代价：部分回退 ADR-052 的"提示迁移"决策（但 ADR-052 删单价列本身不变）；"分组规则/参考区间口径"文字说明删后仅存于列头 tooltip + 代码注释（**必填校验不受影响**——列头红星 / 输入框标红 / placeholder / 后端 400 均独立于 notice）。
- 可逆性：**高**（纯前端展示层，无数据/接口/计算链改动）。
