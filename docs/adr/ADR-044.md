# ADR-044: 交付物支持外部链接（`url`）+ 补齐删除入口

## Status
Accepted（2026-10-22，业务要求「交付物增加删除功能，并支持填入 URL 链接」）

## Context

1. **删除能力其实已存在，只是没入口**：`DELETE /assets/{id}/deliverables/{item_id}`（`api.py:836`，`require_editor`，写审计）+ 前端封装 `removeAssetDeliverable()`（`api/index.ts:753`）都在，但详情页交付物 UI 从未接按钮 —— 属于"接口有、UI 无"的半成品。用户自然感知为"不能删"。
2. **交付物只能挂附件，不能挂链接**：`asset_deliverables` 只有 `file`（单文件散列名，ADR-024）。实际交付物常是外部资源（文档链接、网盘、在线手册、GitHub Release 等），强制上传文件不现实。
3. **`meta` 字段不能兼作 URL**：`meta` 是自由文本（格式/大小/授权范围），塞链接会造成语义污染，且无法做协议校验与点击渲染。

## Decision

### 1. 新增列 `asset_deliverables.url VARCHAR(512) DEFAULT ''`
- 结构迁移放 `main.py::_ensure_migration`，沿用既有幂等模式（`PRAGMA table_info` 判断 → `ALTER TABLE ADD COLUMN` → `print("[migration] …")`），**不写数据迁移、不碰 `_run_once`**（纯结构变更，ADR-031 口径）。
- 存量行默认 `''`（无链接）。

### 2. `file` 与 `url` **可并存**，均非必填
一个交付物可以「只有附件」「只有链接」「两者都有」「都没有（仅登记条目）」。
- 不做互斥：真实场景里"PDF 附件 + 在线文档链接"是常见组合；
- 不做"至少填一个"的强校验：`name` 才是交付物的最小身份，强行要求链接会破坏存量数据的合法性。

### 3. 协议白名单：仅 `http://` / `https://`
- **后端校验**（`services` 层，`400`）：「链接地址必须以 http:// 或 https:// 开头」；长度 ≤ 512。
- **前端同规则校验**（失焦/提交时提示），并保证渲染用 `<a target="_blank" rel="noopener noreferrer">`。
- **WHY 必须白名单**：URL 会被渲染成可点击链接，`javascript:` / `data:` 伪协议 = 存储型 XSS 入口。这是本决策里唯一的安全硬约束，不接受"只在前端校验"。

### 4. 删除入口：只放在交付物详情弹窗
- 位置：交付物详情弹窗底部左侧「删除交付物」（`type="danger"` 文字按钮）+ `ElMessageBox` 二次确认。
- **不放卡片 hover 图标**：交付物是产品交付范围的组成部分，误删代价高（要重新登记名称/分类/版本），放进弹窗多一层确认更稳。
- 确认文案说明副作用：「删除后该交付物的附件文件不再被引用（文件本身保留在文件库，可由管理员清理）」——对应 ADR-030 的 file ACL（失去引用后变孤儿文件，仅上传人/admin 可见）。
- 权限沿用 `require_editor`（商务/管理员）；viewer 不渲染任何编辑/删除入口（与既有口径一致）。

### 5. 展示：卡片与抽屉都要显示链接
资产详情页交付物卡片、产品列表快览抽屉的交付物区，都在附件行旁边显示链接（外链图标 + 可点击，新窗口打开）。仅 `url` 非空时渲染。

## Consequences

- **变容易**：外部交付资源不必先下载再上传；误登记的交付物可自行清理（此前只能连库或找开发）；交付物条目终于能表达"链接型交付"。
- **变难 / 代价**：
  - 新增 1 列（结构迁移，一次 ALTER）；`AssetDeliverableInput/Update/Out` 三处 schema + 前端契约同步；
  - 出现"链接可能失效"的新问题域（404/域名过期）——本次**不做链接健康检查**，属已知边界；
  - 删除后产生孤儿文件（ADR-030 已定义可见性行为），文件库会缓慢累积，需另有人工清理路径（已有 `/upload` 删除接口 + 引用检查）。
- **可逆性：高**。字段加性，删列不影响其他功能；删除入口回退 = 移除按钮（后端端点本来就在）。

## 附：本次不改
- 不引入交付物模板（ADR-024 已下线，不回退）；
- 不做多附件（仍是单 `file`）；
- 不做链接可达性检测/定时校验；
- 不改删除端点的权限与实现（仅前端接入）。
