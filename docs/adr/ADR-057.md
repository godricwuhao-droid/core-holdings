# ADR-057: 审核订单页（review.vue）美化 + 合同勾选部分确认/驳回

## Status
Accepted（2026-11-04，已实现 + QA 独立回归全绿：§1 每合同一张表（容器+合同头[勾选/客户名降级/主体tag/合同总价/小计]+el-table 6 列、行高统一、金额列 center、info-bar、客户名降级）§2 sticky 底部条（已选 N/M+勾选合同合计+确认/驳回、0 勾选禁用）§3 每合同勾选默认全选、部分确认（review 加 contractIds、未勾保持 pending、项目有 pending 保持 pending 可续审）/部分驳回（复用 reject-contracts）、勾全选=整单、[active,pending]→pending 派生、编辑链路+只传变更+校验范围=勾选 全过；QA 首验发现 BUG-ADR057-001（部分确认后剩余 pending 丢失默认勾选）已修复（watch 幂等默认全选）+ OBS-01（勾全选省略 contractIds 走整单日志），复验通过，无阻断缺陷）

## Context
用户觉得**订单审核页**（`frontend/src/views/sales/projects/review.vue`，`/sales/projects/:id/review`）**太丑**，要求**每行订单/合同参考购物车页（`views/cart/index.vue`）展示风格**优化，并**给每个合同加勾选框**（默认全选）控制「确认下单/驳回」作用于**勾选的合同**（部分确认 + 部分驳回，与 ADR-056 详情页勾选驳回统一）。

现状（code-explorer 摸底）：
- **审核页结构**（template 407–621，style 623–972）：页头(411–431) → 权限/未分配提示卡(434–446) → 订单审核 `.form-card`(450–581：`.rv-rules` 说明条 458–465 → 合同块 `v-for .rv-ct` 466–576 → 项目总额 `.rv-foot` 577–580) → 备注卡(584–600) → 底部操作 `.bottom-actions`(603–615)。
- **合同块**（`.rv-ct`，467–575，**非卡片**，仅 1px 分隔线）：合同头 `.rv-ct-head`（客户名 `el-input` 16px/600 大标题级 472–478 + 主体 tag 479 + 右侧「销售金额合计」20px 大字 481–484）；合同总价行 `.rv-ct-amount`（label+tooltip+`el-input-number` 492–501）；明细行 `v-for .rv-line`（**CSS Grid 5 列硬编码** 507–566：产品名/数量/原价/可编辑价/金额）；服务期限（**每行第二层** `.rv-line-svc-row` 568–573）。
- **可编辑字段（核心，不能丢）**：客户名(`reviewContracts[].customer`)、合同总价(`.amount`，**总额权威**)、数量(`l.qty`)、实际单价(`l.price` unit 行)/销售金额(`l.amount` amount·rs 行)、服务期限(`l.serviceStart/End`)、备注。计算链：`lineAmount`(134)→`contractLineSum`(139)→`contractTotal`(145)→`projectTotal`(150)；校验 `contractInvalid`(167)+提交逐行(244–267)；只传变更项(288–316)；确认后合同总价按明细比例分摊（后端）。
- **审核接口**：`POST /projects/{id}/review`（api.py L512–528）→ `review_project`（services.py L2458–2745）——**整项目** confirm（所有合同→active）/reject。ADR-056 已加 `POST /projects/{id}/reject-contracts`（**部分** pending 合同驳回，`_reject_contracts` helper）。
- **购物车页（参考）**：`el-table` 无竖线+stripe、统一 `.cart-cell`（40px 主区+18px 副区，行高一致~90px、输入框严格对齐）、表头一次声明列语义、输入框占满列宽、值驱动标红+列头红星、`sticky` 白卡合计+操作条 `.cart-checkout`（1233–1303）、`.cart-notice` 说明条。**是项目内唯一成熟的 inline 可编辑表格先例**。
- **`core-holdings-ui`**：主蓝 #1769D4、圆角 4 档、边框 3 token、表头底 #F8FAFC/无竖线/行 hover #F8FBFF/8px、金额 `formatMoney`、**金额/数字列 `align="center"`（禁 right，规范）**、`el-input-number :controls=false`、说明条浅蓝 `.info-bar`。
- 审核页「丑」点：无表头（每行内嵌重复灰标签）、合同块无容器（层级弱）、一个合同 4 种版式节奏散、Grid 列宽硬编码窄屏挤压、`.rv-foot`/`.rv-rules` 自造样式非 token。

## Decision

### §1 视觉改版（**方案 A：每合同一张表**）
每个合同 = **一块容器**（10px 圆角 + `--border-color` 边框，合同间清晰分隔）：
| 组成 | 内容 | 规格 |
|---|---|---|
| **合同头**（`.table-head` 范式，仿购物车 L640–649） | 左：客户名 `el-input`（**降级为常规字号**，仿购物车 small input，非 16px/600 标题级）+ 主体 `el-tag`（`entityShort`）；右：**合同总价** `el-input-number`（`:controls=false`）+ **小计** `formatMoney(contractTotal)` | 表头语义一次声明；客户名不再是视觉焦点 |
| **明细 `el-table`**（无竖线+stripe，行高统一） | 列：**产品** / **数量**（`el-input-number`）/ **原单价**（只读 `formatMoney`）/ **实际单价**（unit 行 `el-input-number`）/ **销售金额**（amount·rs 行 `el-input-number`，unit 行显示金额+参考单价）/ **服务期限**（双 `el-date-picker`，**并入单列**，行变单层高） | 列宽由 column 声明（对齐免费）；**金额/数字列 `align="center"`（跟规范）**；`el-input-number :controls=false` |
| **说明条** | `.rv-rules` → 换**全局 `.info-bar`**（浅蓝，规范） | 删自造浅蓝样式 |

- **删除** Grid 硬编码列宽（805–815/868–873）、逐行内嵌标签、`.rv-line-svc-row` 第二层 → 全部明细单行、行高一致、跨列输入框对齐（可参照购物车 `.cart-cell` 骨架思路）。
- **保留全部可编辑字段 + 计算链 + 校验 + 只传变更项提交**（视觉重构，逻辑不动）。
- 参照：购物车页 `views/cart/index.vue`（el-table + 可编辑列 + cell 骨架）+ 项目详情页 `detail.vue` 合同表（`contract-table` 602–832，合同分组+明细子表，同源数据）。

### §2 sticky 底部条（合计 + 确认/驳回）
- **合并项目总额 + 确认下单/驳回 为一条 `sticky` 底部工具条**（照购物车 `.cart-checkout` 1233–1303：`position:sticky; bottom:16px`、白底+`--border-color`+10px 圆角+轻投影）：
  - 左：「**已选 N/M 个合同 · 合计 ¥X**」（合计 = **勾选合同**的 `contractTotal` 之和；N=勾选数、M=可审 pending 合同数；金额 22px/700 主蓝）。
  - 右：「**确认下单**」(primary) + 「**驳回**」(danger plain)。
- **显式豁免**全局非悬浮 `.bottom-actions` 规范（购物车 `.cart-checkout` 本就是既有特例）。
- **勾选数=0 时两个按钮禁用**。

### §3 合同勾选 + 部分确认/部分驳回
| 项 | 决定 |
|---|---|
| **勾选** | 每合同头一个 `el-checkbox`，**默认全选**；审核页只展示**可审的 pending 合同**（`reviewContracts` 过滤 `status==='pending'`；部分操作后已确认/已驳回的合同自动移出、剩余 pending 可续审） |
| **确认下单** | `POST /projects/{id}/review`（`action=confirm`）加**可选 `contractIds[]`**：**只确认勾选的合同**（→active），**未勾选保持 pending**；**项目在有 pending 合同时保持 pending**（可续审），零 pending 后正常派生（active/delivering/delivered/terminated） |
| **驳回** | 复用 ADR-056 `POST /projects/{id}/reject-contracts`（`contractIds` = 勾选 + `reason` 必填） |
| **默认全选** | 一键「确认下单」= 全部勾选 = 与现状整单确认等价（**向后兼容**：`contractIds` 不传 → 全量确认，行为不变） |
| **部分确认后** | 前端 `refresh()`；已确认(active)/已驳回(terminated) 合同移出 review 视图；剩余 pending 可继续确认/驳回；全部处理完 → 项目派生离 pending |

### 后端（§3 支撑）
- `ReviewInput` 加 **可选 `contractIds: list[int] | None`**。
- `review_project` **confirm 路径**：`contractIds` 提供时，**逐合同操作（行级改价/改数量 2574–2651、合同总价分摊 2652–2673、库存锁定调整 2678–2706、服务期限、`c.status="active"` 2738–2740）仅限选中合同**；**未选中合同保持 pending 不动**；守卫（空单/0元/pending_asset）针对**选中集合**；`_recompute_project` 派生。
- **`_derive_project_status` 补/验**：`[active×N, pending×M] (M>0) → pending`（与 ADR-056 `[terminated,pending]→pending` 分支**同口径**：只要有 pending 合同项目就保持 pending 可续审）；全非 pending 时正常派生。
- reject 走 ADR-056 `reject-contracts`（不动）。
- **向后兼容**：`contractIds` 缺省 = 整单确认（现状不变）；`review` 的 reject 路径不动（审核页勾选驳回改走 `reject-contracts`）。

## Consequences
**变容易**：审核页规整像购物车（表头/对齐/行高统一、合同分组清晰）；可部分确认/部分驳回（不必整单）。
**变难 / 风险**：
- **review.vue 大幅重写**（template 466–580 + 大部分 style）——**编辑链路（7 字段 + 计算 + 校验 + 只传变更）是核心，重构不能回归**；QA 重点比对改前后提交体一致。
- **部分确认后端**：`contractIds` 过滤要覆盖所有逐合同步骤 + 守卫 + 派生，**不能破坏整单确认**（`contractIds` 缺省回归）。
- **派生新态** `[active,pending]→pending`：确认该混合态此前是否可能产生（部分确认是新路径），避免影响存量。
- **sticky 条**豁免全局非悬浮规范，注意不影响返回详情/改派等其它操作入口。
**可逆性**：中——前端样式/结构可回退；后端 `contractIds` 向后兼容（缺省整单），派生补分支是新增（可回退）。

## 任务拆分
- **backend-dev**：`ReviewInput` 加可选 `contractIds`；`review_project` confirm 路径按 `contractIds` 过滤（缺省整单不变）；`_derive_project_status` 补/验 `[active,pending]→pending`；自测部分确认（勾 2 确认→2 active、剩 pending、项目仍 pending 可续审；全勾=整单回归；守卫；鉴权/接手人）+ 部分驳回复用 reject-contracts。
- **frontend-dev**：review.vue 重写为方案 A（每合同头+el-table、金额 center、`.info-bar`、客户名降级）+ sticky 底部条（已选 N/M + 勾选合同合计 + 确认/驳回）+ 每合同勾选（默认全选）+ 确认走 review(contractIds)/驳回走 reject-contracts + reviewContracts 过滤 pending；`vue-tsc` 0。
- **QA**：视觉（表格/表头/行高/对齐/合同分隔/info-bar/sticky/客户名降级）+ **编辑链路回归（改价/数量/期限/客户名/合同总价/备注 → 提交体与改前一致、校验、只传变更）** + 部分确认/驳回（部分→项目 pending 续审、全勾=整单、未勾保持 pending、下游锁定/遥感）+ sticky 合计=勾选之和 + 五角色/守卫/权限提示卡 + 护栏（详情页 ADR-056 勾选驳回不回归、detail/review 跳转、确认下单→项目流转）。
