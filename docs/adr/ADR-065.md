# ADR-065: 卫星Token 计价模式归一为普通 unit 商品（去除 amount 特殊处理）

## Status
Accepted（2026-11-10，后端+前端已实现 + 自测/Architect DB 复核 + vue-tsc 0：**后端** `create_asset`/`update_asset` 去"卫星Token→amount"特判（恒 unit）、`main.py` 幂等迁移 `_run_once("ADR065_sat_token_to_unit")`（6 资产 amount→unit、4 购物车 amount 清空、明细 id54 修正 price0.0/amount0.03→0.03/3000 + 合同52/项目32 重算、id41/46 本就一致不动）、区间硬拦自动继承（普通商品本就 400 硬拦）、审核不卡区间保持；`amount` 代码保留为死代码。前端 `assets/create.vue` `isAmount` 去 `type==='卫星Token'` 特判（恒 false）、`constants.ts` note 改 unit 口径；购物车/审核/详情/交付随 `isAmountMode` 归零自动走 unit（小计=单价×数量、超区间标红+结算被拦、实际单价列正常、无 Token 副文案）。**DB 复核**：6 资产全 `unit`、4 购物车 amount 全 `NULL`、id54=0.03/3000、id41/46=30500/91500、迁移标记已登记；**端到端**：asset39 qty100000 单价0.03→小计3000（非0.03）、单价0.033333→400 超区间、审核改价0.05不拦；自测含登记页无 info-bar、普通商品/遥感回归，vue-tsc 0）

## Context
- 用户反馈：购物车下单，**卫星Token** 产品（太空计算大模型TOKEN，assetId 39）输入数量 100000、销售金额 0.033333 后，**小计/应付合计 = ¥0.033333**（=单价本身），而非 0.033333×100000≈3333。**审核页同病**（code-explorer 确认）。
- 根因：卫星Token 被后端**按类型强制 `amount`（包量/总额）计价**（ADR-008，`services.py:667`），`salePrice` 仅参考、不参与计算。amount 模式下「销售金额」输入框语义 = **合同总价**，但 UI hint 写「元/个」误导 + **amount 行跳过区间校验**（前端 `amountOutOfRange` L203 `return false`；后端 `set_cart_qty`/`checkout` 对 amount 行只 `_validate_amount_yuan` 精度校验、不卡区间）。用户把**单价 0.033333** 填进**总价**框 → 小计=0.033333（当总额），且超区间 0.03~0.03 未被拦。
- 购物车（`cart/index.vue`）、审核页（`review.vue`）、后端（`services.py:4313-4316`）**三处同套 amount 口径**，一致地"错"，非前后端不一致。
- **普通商品（unit）超区间 = 硬拦**（后端 `_check_discount_range` `services.py:443-444` 400 + 前端结算拦截 `cart/index.vue:501-512`）；**审核确认不卡区间**（任何商品都不卡，仅 >0 + 6 位小数）。
- 用户决定（2026-11-10）：**卫星Token 彻底按普通商品（unit：单价×数量）走，去除 amount 特殊处理**；区间校验同普通商品（超区间硬拦截）；商品登记页同普通商品；3 条已下单历史明细**人工核对修正**（经数据核对，实为 1 条需修正，见下）。

## Decision
**卫星Token 归一为 unit 计价，与所有普通商品完全一致：**
1. **后端计价模式**：`create_asset`（`services.py:665-667`）/`update_asset`（`793-799`）**不再按类型把卫星Token 置 `amount`** → 全部落 `unit`（默认）。`_is_amount_mode`（`365-367`）判定逻辑保留（对存量仍正确），但迁移后**没有任何商品是 amount 模式**。
2. **区间校验自动继承**：unit 商品超区间硬拦（后端 400 + 前端结算拦截）；卫星Token 归一 unit 后**自动继承**，无需新增校验。**审核确认保持同普通商品——不卡区间**（仅 >0 + 6 位小数），避免对卫星Token 单独加卡而与普通商品不一致。
3. **一次性迁移**（`main.py` 幂等 `_run_once`）：
   - **6 资产**（id 6/7/8/37/38/39）：`pricingMode` `amount`→`unit`（`salePrice` 从"仅参考"变为实际单价；已设的 `priceMin/Max` 现作用于单价）。
   - **4 购物车项**（id 3/20/23/31）：`amount` 清空为 `NULL`（旧值是"总额"语义，unit 下当"单价"会 ×qty 放大/量纲错）→ 清空后按 `salePrice` 参考单价重派生，用户按新口径确认。
   - **3 项目明细**：id 41/46（assetId 37，`30500×3=91500`）**本就 price×qty=amount 一致，不动**；**id 54**（assetId 39，属 **pending** 项目 32）`price=0.0, amount=0.03`（bug 误存）→ 按资产参考价修正 `price=0.03`、`amount=0.03×100000=3000`，并重算其 `contracts.contractAmount` + project 派生额（**待业务在复审中最终确认**，项目 32 可复审）。
4. **前端去除卫星Token 特殊处理**：`assets/create.vue` 的 `isAmount` computed（`L87-91`）**去掉 `type==='卫星Token'` 特判**（新建卫星Token 不再走 amount 展示分支）。其余 amount 展示分支（info-bar `L391-393`、数量提示 `L358-362`、cart Token 副文案 `L695-698`、review/detail/create/outbound 的 amount 分支）**因 `isAmount`/`isAmountMode` 归零后自动失效**（保留为死代码无害，降低回归面）。`displayUnitPrice`（`types.ts:867`，×1e6/百万Token）本已 0 调用死代码。
5. **单位显示**：卫星Token `unit` 本就 =「个」（`constants.ts:25`），归一后同普通商品；cart 的「X Token」副文案随 `isAmount` 失效自动消失。

**接口契约（前后端）**：`GET /assets` 的卫星Token 资产 `pricingMode` 变 `unit`；购物车/审核/结算对卫星Token 走 **unit 口径**（金额框=单价、小计=单价×数量、超区间硬拦）；`POST /assets` 对卫星Token 也落 `unit`。无新端点。

## Consequences
- 易：卫星Token 与普通商品完全一致（单价×数量、区间硬拦、登记页同套），消除"单价当总额"语义陷阱；硬拦截自动继承；改动集中在"去 amount 赋值 + 迁移 + create.vue 一处特判"。
- 难/代价：`amount` 模式代码变死代码（前后端 20+ 处分支不再命中，保留以降回归面，后续可清理）；存量数据迁移（6 资产 + 4 购物车 + 1 明细），id 54 历史金额修正需业务最终确认。
- 可逆性：**中**——逻辑可逆（恢复 amount 赋值 + 反向迁移），但涉及数据迁移 + 死代码，回退需回归测试。
