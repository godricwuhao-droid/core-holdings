# ADR-052: 购物车销售金额双向区间约束 + 去除「销售单价」列

## Status
Accepted（2026-11-04，已实现 + 实测通过：后端 curl 双向往返（unit 超上限 2061→400 / 低于下限 1999→400 / 区间内 2030→200；amount 包量超上限→200 不卡）、前端浏览器实测（销售单价列已删、越界 3000→红标 / 区间内 2030→不红、点结算越界拦截提示「销售金额须在参考区间内」）、vue-tsc 0）

## Context
- **ADR-049（2026-10-29）** 曾刻意把购物车放宽为「**只卡下限**」：购物车加购/改数量/改金额/结算（任何角色）金额可**高于参考区间上限**，仅低于下限 → 400。当时的考量：参考区间是「指导价」，允许在购物车高于上限成交。
- 业务现要求**反向收紧**：购物车「销售金额（元）」输入**必须落在参考区间内**（低于下限、高于上限都禁止）；但**商务审核改价**仍**不受区间限制**（审核是兜底，可设任意 >0 价）。
- 另：购物车表格「销售单价」列是**纯展示派生**（`row.price` = 挂牌价/明细价，`cart_items` 无 price 列，小计与结算 payload 均不依赖它），信息被「参考区间」提示取代 → 去掉，让表格更聚焦。

## Decision

### 1. 购物车销售金额双向区间约束（**部分取代 ADR-049 的「只卡下限」**）
后端 `_check_discount_range` 的**购物车 4 个入口** `enforce_max=False → True`（同一判定式，`enforce_max=True` 即上下限同时卡）：
- `_cart_add_inner`（`POST /cart` + `/cart/batch`）
- `patch_cart_item`（`PATCH /cart/{id}` 改客户/改金额）
- `set_cart_qty`（`PUT /cart/{id}` 改数量/改金额）
- `checkout`（`POST /cart/checkout`，含对**全量行**重校验，并透传 `_create_project_core`）

效果：**unit 行（含遥感行）销售金额低于下限 400 + 高于上限 400**。

用户拍板的三条边界：
- **包量/Token（amount 模式）行不覆盖**：仍走 `_cart_amount`（仅 >0 + ≤6 位小数），**不卡区间**（量纲：区间是元/单位，合同总价不匹配；包量行本就不进 `_check_discount_range`）。
- **商务审核改价不限制（不变）**：`review_project` 本就不调区间函数 → 保留（这是高于上限成交的**唯一合规出口**）。
- **商务手工建单双向（不变）**：`_create_project_core` 默认 `enforce_max=True` → 保留。
- 兜底（不变）：未设区间=不限；单边=只卡有值侧。
- **存量超上限行**：结算时 400 拦截，改回区间内即可结算（无数据迁移）。
- 比较口径（不变，2026-10-29 起）：`cart_items.amount` 原值**直接** vs `[priceMin, priceMax]`，不 ÷qty（unit 行 amount=单价、量纲一致；遥感 qty≡1）。

> **合规出口提示**：收紧后，购物车与手工建单都双向硬卡；若业务需**高于上限**成交，走**审核改价**（不受区间限制）。

### 2. 前端（`frontend/src/views/cart/index.vue`）
- **去「销售单价」列**（纯展示派生）；其副提示区的「**可售 N / 已达上限 N**」hint **迁移**到「销售金额」列副提示（与区间提示合并，不丢信息）；价格参考由「销售金额」列下的**参考区间提示**承接。
- **销售金额输入（`el-input` 文本）加双向区间校验**：非 amount 行 + 区间已设时，`n < priceMin` 或 `n > priceMax` → 标红 + 阻断结算；数值 min/max 复用现有 `priceRangeText` 数据源；区间提示文案改双向语义；顶部提示条「上限不限制，可高于上限成交」→「须在参考区间内」。
- **amount 行前端同样不加区间校验**（仅 >0 + ≤6 位小数），与后端一致。

### 3. 不变量（回归护栏，QA 必测）
- 审核改价仍不限区间（仅 >0 + ≤6 位小数）。
- 手工建单仍双向。
- 包量行仍不卡区间。
- 数量锁定/结算/派生不变量不受影响（仅新增一道金额区间闸）。
- 销售单价列去除后：小计、结算 payload、落库金额**零变化**。

## 接口契约
| 项 | 契约 |
|---|---|
| 后端 | 购物车 4 入口 `enforce_max=False→True`；报错文案沿用 `销售金额超出该产品参考区间（{区间}）`；包量行/审核/手工建单不变 |
| 前端 | 销售金额输入：非 amount 行 + 区间已设 → 须 `min ≤ n ≤ max`，否则标红 + 禁结算；amount 行不校验；顶部/行内提示改双向 |

## Consequences
- **变容易**：购物车金额有硬约束，防误填超区间价；去冗余列、表格聚焦。
- **变难**：购物车从「上限开放」变「双向硬卡」——高于上限的成交改走**审核改价**；存量超上限购物车行需改回区间内才能结算。
- **可逆性：高**——4 处 `enforce_max` 翻回 `False` 即回到 ADR-049；去列可还原。
